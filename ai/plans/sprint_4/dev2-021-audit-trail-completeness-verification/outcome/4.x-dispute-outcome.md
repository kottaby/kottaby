# Outcome 4.x — Dispute Arbitration Emission (Phase 4)

**Task**: 4.1 + 4.2 + 4.3 · **Date**: 2026-09-09 · **Executor**: Dispute Emission Subagent + Orchestrator completion pass

## Summary

`resolveSessionDispute` now mints exactly one audit row per successful arbitration through `AuditService.createAuditLog` on the arbitration's own transaction. Zero signature change: the method's existing `adminId`, admin gate, and `withTransaction` block were reused as-is. The emission is placed strictly AFTER the guarded state flip and (for the Cancel outcome) after the same-lane refund — an audit failure throws, so a partially-applied arbitration can never commit, and the trail can never record an arbitration whose writes did not land.

## Carry-forward knowledge

1. **Denial taxonomy**: bad-state arbitration denials are `SESSION_INVALID_TRANSITION` (disputed-state guard); only COMPLETE-on-never-started is `VALIDATION`. Tier-4 zero-mint tests must assert the code the guard actually throws.
2. **Guarded-once actions have no repeat-mint tier**: a terminal (cancelled/completed) session cannot re-enter dispute, so the plan's rerun-repeats oracle does not apply to `resolveSessionDispute` (its side-effect matrix marks it "guarded once"). Append-only honesty for repeatable actions is exercised at journey level instead.
3. Row-level helpers returning pg-enum columns: widen via an explicit map return-type annotation (`(row): { actionType: string; ... } =>`), NOT `as string` (type-aware lint flags it unnecessary) and NOT spread-in-map (oxlint `no-map-spread`).
4. The arbitration emission rides the SAME tx as the refund — ordering is update → refund → audit, so a rolled-back refund can never leave a trail row behind.
