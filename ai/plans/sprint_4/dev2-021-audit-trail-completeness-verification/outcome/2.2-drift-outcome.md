## 1. Summary

Created the static, DB-free anti-drift lock that keeps the shipped admin-gated mutation inventory and the admin action census in exact bijection. It shares the corpus-walk *pattern* with the sibling `audit-immutability.test.ts` suite but is a separate suite with a separate contract (census completeness vs append-only immutability). Zero database operations, zero network calls, zero filesystem writes — read-only `node:fs` traversal + pure regex classification.

## 2. Extraction mechanics

- **Corpus walk** — `listSourceFiles` recursively collects `.ts` files under `backend/graphql/mutation/`, deterministically sorted (`localeCompare` at read time), skipping `node_modules`; labels are corpus-root-relative so any finding names the owning file.
- **Chunking** — `MUTATION_FIELD_DECLARATION_PATTERN` splits each file into one chunk per quoted `gqlSchemaBuilder.mutationField("<name>"` registration (the quote is required so comment mentions never split chunks).
- **Gate classification** (`classifyAdminGate`, pure) — per chunk: no `authScopes` key → `non-admin` (public); a statically resolvable `role: [...]` leg (plain map **or** nested inside `$all` conjunction — both accepted forms) containing `UserRole.Admin` → `admin` (ANY semantics); non-literal `authScopes` value, unbalanced literal, non-array `role:` value, or non-static role member → `unclassifiable`.
- **Unparseable-gate honesty** — `unclassifiable` results are never dropped: they land in a recorded skip ledger (`<file>#<field>`) and a dedicated assertion requires that ledger to be **empty** for the current corpus. Zero skips today.
- **Module-level extraction** — corpus + scan are computed once at module load as immutable snapshots (no mutable module state).

## 3. Assertion inventory (18 tests → what each guards)

Tier 1 — corpus extraction:
1. corpus populated (≥10 files) + 6 sentinel paths present (`admin-users`, `admin-governance`, `admin-teachers`, `admin-broadcast`, `session-lifecycle`, `plan-catalog` mutations) → the walk cannot silently scan an empty/wrong subtree.
2. skip ledger empty → no gate is silently guessed or dropped.
3. extracted admin field names unique → duplicate registrations cannot mask drift.
4. extraction floor ≥ 11 fields (`MIN_ADMIN_MUTATION_FIELDS`) → the scanner cannot go blind and still pass.

Tier 2 — bijection:
5. extracted admin set ≡ census wired set in BOTH directions → the core lock: an unaudited admin mutation fails, a stale census row fails.
6. census wired field names distinct → duplicate census rows cannot fake coverage.
7. wired rows carry non-empty verbs and no ledger ref; deferred rows always carry a `D-\d{3}` ref → row-schema hygiene.
8. deferred rows start with `(future)` and never appear in the extracted set → future surfaces cannot collide with shipped fields.

Tier 3 — ledger traceability + enum coverage:
9. every deferred `deferredRef` exists among the `D-0xx` row ids read from the deferred-items ledger (missing ref falls back to an id no row carries → loud failure) → deferrals stay owned and traceable.
10. per-verb `ACTION_TYPE_COVERAGE` expectations (6 verbs `wired`, `Adjust` `fixture`) → enum-member accounting cannot rot.
11. every verb emitted by a wired census row is marked `wired` in the coverage map → census ↔ coverage-map consistency.

Negative self-test harness (non-vacuity):
12. classifier fires on the plain-map admin gate.
13. classifier fires on the `$all` conjunction form.
14. classifier stays silent on permission-gated, non-admin-role, and public fields.
15. classifier records `unclassifiable` instead of guessing on shared-constant and dynamic-role gates.
16. full scanner extracts injected admin fixtures (and only them) from crafted in-memory files.
17. injecting an extra extracted field reports exactly `[field]` as missing-from-census (and nothing else).
18. injecting a phantom wired census row reports exactly `[field]` as unwired (and nothing else).

## 5. Negative harness proof

The scanner/bijection are pure functions over `(path → content)` maps, so the harness feeds crafted in-memory fixtures that MUST fire: both accepted admin-gate forms, three non-admin shapes, two unresolvable-gate shapes, a full two-file crafted corpus, and both drift directions (extra extracted field; phantom census row). A broken or over-permissive scanner therefore cannot fake green — assertions 12–18 pin both sensitivity and specificity, and 17/18 pin exact single-element reports (no over-reporting).

## 6. Carry-forward knowledge for later tasks

- **New admin mutation + no census row = CI failure.** Shipping any new `role: [UserRole.Admin]`-gated `mutationField` without adding a census `wired` row breaks test 5; conversely, removing/renaming a mutation without updating the census breaks it in the other direction. This is the enforcement backbone for the plan's "census-before-admin-mutation" rule.
- **Corpus sanity floor is 11** (`MIN_ADMIN_MUTATION_FIELDS = 11`), re-based from the plan's original ≥9 to absorb the two account-governance mutations; the file-count floor (≥10) and 6 sentinel paths guard the walk itself. If a legitimately gated surface is added, raise the floor in the same change as the census row.
- The ledger traceability assertion (test 9) reads the plan directory's `deferred-items.md` at runtime — if the ledger file moves, the drift test fails loudly (`Deferred-items ledger not found …`), by design.
- Gates written in a new form (non-literal `authScopes`, computed role arrays) will be recorded as unclassifiable and fail the empty-skip-ledger assertion — extend the classifier *and* its negative fixtures together.
- The suite is intentionally DB-free: do not add DB fixtures or `runInRollback` here; row-shape verification belongs to the 5.x journey.
