## Carry-forward knowledge (for 4.x / 5.x / reviewers)

1. **Savepoint interleave gotcha (critical)**: `withTransaction(tx, fn)` nests via `outerTx.transaction(fn)` (a SAVEPOINT) when a tx is supplied. Two concurrent service calls sharing ONE test transaction interleave savepoint windows; the loser's `ROLLBACK TO SAVEPOINT` silently clobbers statements the winner issued inside that window (observed: winner's audit INSERT vanished while its own UPDATE result stayed intact). Production is unaffected (each resolver owns a real pool transaction; row locks serialize). Rule: **never inspect row-level outcomes of concurrent service calls that share one test transaction** — assert call-level classification only, and prove trail consistency with a deterministic sequential flow.
2. The service gate needs a REAL admin row — GraphQL-layer tests exercising admin mutations must resolve the seeded admin (`ADMIN_EMAIL`) instead of fabricating mock ids; commit-write fixtures must be tracked and cleaned (audit rows first, under trigger suspension).
3. `rawActionType(AuditActionType.X)` widening is the canonical way to compare enum members against raw DB strings (oxlint `no-unsafe-enum-comparison`).
4. Seeded-admin cleanup discipline: delete audit rows for tracked entity ids under `withAuditDeleteTriggersSuspended`, then delete the entity rows.
