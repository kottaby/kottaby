### Upgrade path (documented per tasks.md 0.2; carried into runbook Task 6.1 prerequisites)

- Rule: `pg_dump`/`pg_restore`/`psql` client major version MUST be **>=** the server major version it targets. The PostgreSQL project does not support older-client dumps of newer servers (pg_dump specifically refuses/fails on newer server majors).
- Current state: client 17.x == server 17.x → OK.
- If the **server** is upgraded later (e.g., Neon moves to 18, or the local cluster is re-initdb'd on a newer major), the **client tools must be upgraded in lockstep** (same major or newer) before backup tooling will pass its probe. Conversely, dumps produced by a newer `pg_dump` cannot be restored by an older `pg_restore`.
- Operational consequence for `backup-database.ts` (Task 2.1): the toolchain probe must parse major versions from `pg_dump --version` and the server, compare numerically, and exit 2 with install/upgrade guidance when `client < server` (REQ-010.3).
