## Deviation — no runInRollback

The repo's rollback-wrapper test pattern is not applicable to this drill: it shells out to OS-level tools (`createdb`, `pg_dump`, `pg_restore`, `psql`) that cannot participate in an application-level transaction. Isolation is therefore achieved at the only boundary available to OS tools — uniquely-named per-run scratch databases, template-copied from the dev database so schema plus seed fixtures cover every critical table — with the real PASS chain, the guard probe, and the tamper-FAIL chain run against them, and full teardown (database drops + tmpdir removal) in `afterAll`. The dev database serves strictly as a read-only template source and is never written. The deviation is documented in a clean domain-language header comment in the test file.
