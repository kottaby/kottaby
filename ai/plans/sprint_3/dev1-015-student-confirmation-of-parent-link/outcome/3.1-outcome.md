## 6. Root cause of the wire-suite red (environmental, carry-forward)
The wire harness runs a spawned Next dev server AND the test process each with its OWN
in-process PGlite on `./db/pglite`. A PGlite instance reads the data dir only at OPEN:
the test instance opens at its first direct-db query (pool memoized in `backend/db/client.ts:214`)
and never sees the live server's later commits (registrations) — the students-row read at L639
misses rows the server committed seconds earlier (proved: a fresh post-run process reads all rows).
Reproducers: fresh `db/pglite` rebuild (migrate+seed) → same L639 failure; zombie dev servers on
:3066 intermittently break registration entirely; parallel-registration suites additionally hit
the single-session savepoint-sp1 collision (the new sequential `registerActorCast` already
removes that mode for this file). Verdict: pre-existing infrastructure limitation affecting ALL
wire suites under `DB_PROVIDER=pglite`, NOT a defect of the 3.1 cells.
