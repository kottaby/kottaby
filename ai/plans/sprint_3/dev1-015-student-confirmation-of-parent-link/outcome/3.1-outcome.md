## 6. Root cause of the wire-suite red (environmental, carry-forward)
The wire harness runs a spawned Next dev server AND the test process each with its OWN
in-process PGlite on `./db/pglite`. A PGlite instance reads the data dir only at OPEN:
the test instance opens at its first direct-db query (pool memoized in `backend/db/client.ts:214`)
and never sees the live server's later commits (registrations) — the students-row read at L639
misses rows the server committed seconds earlier (proved: a fresh post-run process reads all rows).
Reproducers: fresh `db/pglite` rebuild (migrate+seed) → same L639 failure; zombie dev servers on
:3066 intermittently break registration entirely; parallel-registration suites additionally hit
the single-session savepoint-sp1 collision (the new sequential `registerActorCast` already
removes that mode for this file). Verdict: pre-existing infrastructure limitation affecting ALL
wire suites under `DB_PROVIDER=pglite`, NOT a defect of the 3.1 cells.

### Suite 1 — two sequential beforeAll blockers, diagnosed and resolved

1. **Environmental: seeded admin missing from the migrated DB.** Exact error: `error: login
   failed for admin@test.com` at `loginActor` (wire test L509, called from L572). The migrated
   `app_db` had **0 users** (only 3.1's own earlier fixture rows): migrations create tables but
   do NOT seed. Fix (environment only, no repo edit): ran the idempotent seed CLI
   `bun --no-env-file run scripts/dbActions/cli-entry.ts seed` → admin@test.com created (id 7),
   plans/students seeded. Not a fixture bug.
2. **Fixture bug in 3.1's own diff (exposed by real PG — first time the wire suite ever reached
   the fixture).** Exact error: `23505 duplicate key value violates unique constraint
   "parent_link_requests_pending_pair_unique"` on the beforeAll 3-row batch insert. Root cause:
   the new already-EXPIRED seeded row was `status=Pending` on the SAME pair as the live pending
   row (parentP → studentS); the partial unique index forbids **two pending rows per (parent,
   student) pair regardless of expiresAt**. Under pglite this was unreachable (§6 blocker), so
   the index interaction was never exercised. Fix (surgical, semantics-preserving): moved the
   expired row to the (parentP → **studentG**) pair — whose other row is `Rejected`, outside the
   pending-only predicate — and repointed the expired-leg responder + zero-emit notification
   probes to studentG (expired insert now L674-680, expired-leg cell L1274+). All pair-level
   pending collisions audited before the edit: the only row-creating emit remains parentP →
   studentH; no emit ever targets (parentP, studentG). 3rd run: **25 pass / 0 fail / 474
   expect()** — all 25 wire cells green on real PG, including the added expired-claim/BOLA/
   input-coercion/BOPLA cells.
