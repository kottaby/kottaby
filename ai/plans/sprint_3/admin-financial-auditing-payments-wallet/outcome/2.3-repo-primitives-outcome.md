### `backend/db/repo/billing/student-payment.repository.ts`

### `backend/db/repo/billing/wallet.repository.ts`
- `findAdminWalletProbe(teacherId, tx?)` — one joined read wallet→teacher→users; null when no wallet.
- `listTransactionsForAdmin(walletId, filters, limit, offset, tx?)` + `countTransactionsForAdmin` —
  wallet-scoped filter chain, `id DESC`.
- `listPendingWithdrawals(limit, offset, tx?)` + `countPendingWithdrawals(tx?)` — predicate EXACT
  parity with the analytics counter (`type=Withdrawal AND status=Pending`); `id ASC` (longest-waiting
  first per REQ-3 AC2); joined `teacherName` + `walletBalance`.
- `findSettlementProbe(transactionId, tx?)` — `{id, walletId, amount, type, status}` projection;
  pgEnum-derived values narrowed to the TS enums by two exhaustively-guarded mappers (lexical
  identity, no behavior change).
- `settleWithdrawalOnce({transactionId, nextStatus}, tx?)` — guarded single UPDATE
  `WHERE id=? AND type='withdrawal' AND status='pending'` RETURNING; defensive repo guard: any
  nextStatus other than Completed|Failed returns null without touching the row.
- `restoreWithdrawalDebitOnce({walletId, amount}, tx?)` — single additive `balance + amount` UPDATE.
- `creditBonusOnce({walletId, amount, description}, tx?)` — `bonus/completed` ledger INSERT +
  additive balance increment (totalEarning untouched); throws on zero ledger rows.
- `debitAdjustmentOnce({walletId, amount, description}, tx?)` — `withdrawal/completed` ledger row
  inserted FIRST, then guarded `balance - amount WHERE balance >= amount` RETURNING; null on miss
  (the caller's tx rollback removes the ledger row — asserted in the test).

All: `tx?: DBTransaction` LAST param, `sql` template balance arithmetic (no inline `--` comments in
any template — regex-verified), enum members, no i18n/logging.
