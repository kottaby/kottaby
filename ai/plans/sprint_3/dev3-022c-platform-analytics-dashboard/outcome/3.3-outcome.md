## 6. Deviations / observations

1. **All-in-process tier (HTTP declined)** — decision recorded in §1; the task card's conditional ("HTTP tier … when the port window allows") resolved against it on spy-observability grounds (the decisive factor), plus zero new wire-only surface for a zero-argument query and no live server in the sandbox. 2. **In-process `DateTime` leaves arrive as `Date` instances** — graphql-scalars v2's default `DateTime.serialize` returns the validated `Date` object itself (the ISO-variant scalar would stringify); the HTTP JSON layer renders it as the ISO-8601 UTC string. The suite pins BOTH halves (instance + JSON-transport ISO format) — this is why the first run had one red test ("expected an ISO string generatedAt") before the assertion was corrected to the actual scalar contract.
3. **Pre-resolver cells use context-only user stand-ins** (no DB rows) — per the handshake precedent; the three denied roles and anonymous never reach data access, so fixtures would be dead weight. DB-backed cells (happy path, governed) use REAL rows because the service gate re-reads the actor from PostgreSQL.
4. **The `id`-selection probes assert the validator tier** (`Cannot query field "id"`) rather than execution — identical to the handshake suite's behavioral no-id proof; complemented by the per-type SDL pins already shipped in `sdl-static-assertions.test.ts`.
