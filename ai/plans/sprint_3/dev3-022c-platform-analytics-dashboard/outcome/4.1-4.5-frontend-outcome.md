## Harness defect discoveries (4.4.TE bring-up — load-bearing for future suites)

1. **`next-dynamic-mock` eager loader poisoning** — the previous revision
   invoked the loader at `dynamic()` call time to sniff synchronous
   re-exports; that eager `import()` resolved+cached the REAL module in
   bun's registry before any test-file `mock.module` could register
   (static imports evaluate before module-body statements). Fix: fully
   lazy loader contract (resolved on mount via microtask) — which is also
   the true `next/dynamic` semantic.
2. **`isComponent` accepted module namespaces** — `"any non-null object"`
   passed the guard, so ES module records were returned verbatim as
   "components" and the `.default` extraction branch was dead code →
   "Element type is invalid". Fix: functions + `$$typeof`-bearing React
   exotic objects only.
3. **Functional-updater trap** — `setComponent(componentFn)` makes React
   CALL the freshly-resolved component as a functional updater with the
   previous state as props (the source of both the original
   "Cannot destructure 'points' from null" crash and the follow-up
   "got: <div />" state). Fix: `setComponent(() => componentFn)` with the
   rule documented in the mock header (note 3).
4. **bun `mock.module` specifier keying** — mocks did not intercept
   relative `import("./SessionTrendChart")` loaders when registered under
   the `@/` alias (and vice-versa). Fix: `AnalyticsTrendCharts` dynamic
   loaders now use the `@/` alias specifier — matching the codebase-wide
   sibling-import style (the container itself imports siblings via `@/`)
   and letting test stubs intercept.
