## IMPL DEFECT FOUND AND FIXED (during suite green-ing)

- `bucketStart` projections (`getSessionDailyTrend`, `getRevenueDailyTrend`) leaked
  the pg driver's RAW TEXT payload (`"2026-08-01 00:00:00"`) instead of a `Date` —
  the wipe lost the original run's `UTC_TIMESTAMP_DECODER` hardening. The service's
  `trendBucketKey` skeleton merge would have crashed on strings.
- FIX (this commit, repository file): module-scope `UTC_TIMESTAMP_DECODER`
  (`{ mapFromDriverValue }`) attached via drizzle `.mapWith()` to BOTH
  `date_trunc('day', …)` projections — explicit component extraction reassembled
  through `Date.UTC` (never `new Date(text)`, whose bare-datetime branch parses as
  LOCAL wall-clock); `Date` payloads pass through untouched (driver-agnostic).
- Verified by probe: decoder returns a real `Date` at the exact UTC-midnight epoch.
