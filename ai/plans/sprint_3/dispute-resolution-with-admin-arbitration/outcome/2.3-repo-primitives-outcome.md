## Carry-Forward Knowledge for Task 2.5 (service) & 3.1

- **Null semantics (exact contract):** `null` from any primitive means zero rows matched — unknown id, non-participant, wrong state, wrong escrow class, or (wallet) insufficient funds. Disambiguation belongs to the caller via `findArbitrationProbe` (classification-only read, safe to call inside the arbitration tx before the write; the write predicates re-assert the classification, so a drifted read cannot pass).
- **Tx expectations:** every primitive takes `tx` as its LAST parameter (optional; `tx ?? db` fallback). The arbitration outcome legs (resolve → wallet debit → lane credit → audit row) must share ONE caller transaction: `resolveConsumedDisputeOnce`'s returned probe (fee/teacherId/heldBalanceLane/confirmedByStudentAt) feeds the debit + lane legs with no re-read. On wallet null the caller must throw to roll the compensating ledger row back (primitive alone leaves the in-tx row visible until the tx fails).
- **Probe type stance:** `status` is the raw pgEnum union (`"disputed"` etc.), `feeHeld` is `boolean | null`, `heldBalanceLane` is `HeldBalanceLane | null` — map to TS enums at the service/Pothos boundary (`toSessionStatus` precedent); do NOT re-type the probe.
- **Wallet debit unit:** `debitForArbitrationOnce` accepts any `amount ≤ balance` decimal string (Refund → `session.fee`; PartialRefund → validated partial). Amount validation (0 < amt < fee, 2dp precision) is service-layer work — the repo trusts the caller, stores verbatim.
- **Never-held defensive case:** a disputed consumed row with `heldBalanceLane = null` resolves normally; the caller's student lane-credit leg must no-op on the null lane while the teacher debit still applies (REQ-2.4; repo-level proven by the crafted-row test).
- **Race precedent:** the `Promise.allSettled`-on-one-tx pattern (single rollback connection serializes statements; losers' guarded predicates match zero rows) is the repo suite's established concurrency harness — Task 2.5's double-arbitrate chaos test should reuse it, with real cross-connection races left to the journey suite (Task 2.4, committed fixtures).
