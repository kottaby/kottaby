### 1. Created `docs/sessions/dispute-arbitration.md` — the canonical arbitration reference

Section list:

1. **Why** — post-confirmation recourse (B.18) after escrow consumption; the four failure modes that shaped the rulings (double resolution, cross-family outcome application, stranded reversal legs, note-content leakage).
2. **The Two-Generation Dispute Model** — held escrow (`fee_held = true`: either participant, from `scheduled`/`started`, outcomes `Cancel | Complete`, byte-stable, notification-silent, owned by session-lifecycle) vs consumed escrow (`fee_held = false`: student-only, from dual-confirmed `completed`, outcomes `Refund | PartialRefund | Uphold`); the persisted `fee_held` value on the disputed row is the discriminator; one queue covers both generations; dispute-focused mermaid diagram.
3. **Classification Rule & the Resolver Pre-Gate** — `resolveSessionDispute` stays the single entry; family dispatch (`Cancel|Complete` → lifecycle service; `Refund|PartialRefund|Uphold` → `SessionArbitrationService.arbitrateDispute`); `assertResolutionFamilyMatchesEscrow` pre-gate rejects cross-family submissions with localized `disputeResolutionMismatch` BEFORE any write; why the gate is load-bearing (held-family value routed into the held service = double-resolution window); gate advisory-in-race / authoritative-for-vocabulary; both services re-classify inside their own transactions (write predicates re-assert `status` + `fee_held`); `resolveDisputeOutcomeOptions(feeHeld, t)` as the single frontend vocabulary source.
4. **The Exactly-Once State-Machine Legs** — `completed → disputed` student open (full fused predicate, SET columns, oracle collapse incl. the row's own teacher, zero audit rows, exactly-once); `disputed → completed` arbitration completion leg (fused predicate, returning-probe feeds the financial legs with no re-read); fixed transaction composition (completion leg FIRST → wallet reversal → lane credit → audit row → wave receipts → response re-read) so a race loser never moves money; no `FOR UPDATE` needed; `WALLET_INSUFFICIENT_FUNDS` fail-closed rollback leaves the session `disputed`.
5. **The Quantized Student Refund Ruling** — integer session-credit lanes (INV-B1); Refund AND PartialRefund restore ONE full session credit to the provenance lane; the partial quantum moves only on the teacher's money ledger; platform absorbs `fee − partialAmount` worth of the restored credit, recorded per row in audit details; NULL `held_balance_lane` → credit leg no-ops, teacher debit still applies.
6. **The Compensating Withdrawal-Row Pattern** — append-only `teacher_transaction` `{type: withdrawal, status: completed, sessionId, amount}` INSERT + guarded `balance >= amount` UPDATE in one tx; null → caller throws → compensating row rolls back (either both effects or neither); `total_earning` never decremented (gross lifetime counter, INV-W2); decimal strings bound verbatim, never re-parsed/re-rounded; reuse of the `withdrawal`-type forced-debit precedent instead of migrating a governance-pinned pgEnum.
7. **Notification Waves (consumed generation only)** — `session_dispute_opened` → every admin; `session_dispute_resolved` → student + teacher; claim keys `session:<id>:dispute-opened|dispute-resolved` (id + wave kind only, no occurrence stamp needed); in-tx receipts sharing the arbitration tx fate; module never publishes — publish-after-commit owned by the transaction owner; server-side recipient scoping; per-recipient locale; outcome-factual copy; ZERO waves for the held generation.
8. **Audit Convention** — exactly one `override` row per committed arbitration, same tx, composition-only writer; details `{resolution, refundAmount|partialAmount|null, notePresent}`, amount key absent on Uphold, NEVER note content; denials write zero rows; audit insert failure rolls back the arbitration.
9. **Admin Case-Review Read Surface** — `adminDisputeCase` bundle (session detail + report incl. `studentRatingByTeacher` + homework + recitation + session audit trail); honest nulls; one round trip with concurrent reads; admin-gated posture (no participant-oracle arm); read-only.
10. **Boundary With Sibling Surfaces** — Admin Session Governance (browse/reschedule/cancel/reassign/join; disputed rows unreachable there; single arbitration write path now covers BOTH generations); Admin Financial Auditing (gateway money refunds/reconciliation — this surface reverses internal ledger value only); Student Evaluation (student-rates-teacher content; case review is the forward integration point); pre-completion dispute semantics byte-stable in session-lifecycle.
