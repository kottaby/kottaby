## Defect found + fix (browser-verified)

**DEFECT-1 (functional/visual): the code chip was NOT fixed-pitch in the real browser.**
- Symptom: computed `font-family` on the chip Typography was `Inter, "Inter Fallback", Cairo, …` (inherited proportional font).
- Root cause: `MONO_FONT_FAMILY = "var(--font-jetbrains-mono), monospace"` — the `--font-jetbrains-mono` variable is **never mounted anywhere** (`app/layout.tsx` loads only `--font-inter`/`--font-cairo`; repo-wide grep shows only `theme/typography.ts` + this component reference it). An undefined `var()` with no fallback *inside the var()* makes the whole declaration invalid-at-computed-value-time → inheritance — the trailing `, monospace` never applied.
- Fix (scoped to the plan-owned component): `frontend/views/students/dashboard/HandshakeCodeCard.tsx` — `MONO_FONT_FAMILY` is now the literal fixed-pitch stack `"JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace` (offline-safe; no dependency on an unmounted CSS variable).
- Post-fix browser verification: computed chip `font-family` = the full mono stack; all BS captures + pixel analysis taken post-fix.
- Re-verification: `bun run test:ui:components` → **52 pass / 0 fail / 1 snapshot (6 files)**; `bun run scripts/health/sub-loop.ts frontend/views/students/dashboard/HandshakeCodeCard.tsx --lifecycle duplicates` → **exit 0**.
- Out-of-scope observation for a follow-up: `frontend/providers/theme/typography.ts:146` (`typography.mono`) carries the same unmounted `var(--font-jetbrains-mono)` reference — equally broken app-wide, but NOT touched by this task (zero production modification beyond plan-owned files).
