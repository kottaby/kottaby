## 3. Copy decisions

**Terminology grounding:** the existing `auth` namespace already frames the feature — en `roleParentHelper` says "their unique **handshake code**"; ar uses "رمز … لربط" (a code to link). → English says "handshake code" throughout; Arabic uses **"رمز الربط"** (linking code) — purpose-descriptive, natural MSA, consistent with the auth ar copy and the parent-linking domain (avoids the awkward literal "المصافحة"). Arabic for "student" = "الطالب" (matches `dashboard.students` = "الطلاب"); neutral miss copy is identical for every miss reason (no existence oracle — D4 null channel keeps "never existed" and "governance-excluded" indistinguishable).

**Arabic bidi note:** the format-teaching sentence was phrased with the conjunction "وتتكون من 8 خانات سداسية عشرية" instead of a parenthetical after the Latin token, so no `)` + weak-direction run ever trails `KSB-XXXXXXXX` inside RTL text (the repo's existing ar copy embeds Latin runs plainly — e.g. `invalidLocale` embeds "en, ar" — and uses no bidi control characters; followed suit). The code atom itself stays LTR-by-isolation at render time (plan §5.5 RTL rule — task 4.2/4.3 concern).

**SEC copy review (1.4.SEC):** `studentHandshakeNotFound` = "Student record not found." is the `myHandshakeCode` own-row-miss message (NotFoundError("STUDENT") per REQ-050) — it never answers the discovery question; discovery misses are the `null` payload (D4) rendered through `notFoundTitle/Description`, whose copy is identical for every miss reason. `invalidFormat`/`handshakeCodeInvalid` teach the FORMAT only: the embedded placeholder `KSB-XXXXXXXX` contains `X` (not a hexadecimal digit) so it is provably NOT a working code; no valid code is enumerated anywhere. Reviewed identically for Arabic. All of this is machine-pinned by the new parity suite (§5, lock #3).
