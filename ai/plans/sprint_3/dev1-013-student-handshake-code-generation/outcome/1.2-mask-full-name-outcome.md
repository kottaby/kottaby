## 2. Implementation Summary (contract compliance)

- **Trim → placeholder:** `fullName.trim()`; empty-after-trim → `MASK_EMPTY_PLACEHOLDER` (`"***"`, documented constant).
- **Split + per-part mask:** split on `/\s+/u` (stateless — no `g`/`y` flags, so no `lastIndex` state); each part → first grapheme cluster + `MASK_CLUSTER` (`"***"`); parts joined with single spaces. Verified: `"أحمد محمد"` → `"أ*** م***"`, `"Yusuf"` → `"Y***"`, `"ع"` → `"ع***"`.
- **First grapheme:** `new Intl.Segmenter(undefined, { granularity: "grapheme" })` (locale-free — `undefined` locale arg per the design contract); first segment via array destructuring from the `Segments` iterable. Fallback when `Intl.Segmenter` is unavailable: `Array.from(part)[0]` (code-point fallback — never splits surrogate pairs). Availability is checked **per call** (NOT module-load), which keeps the fallback runtime-testable and avoids module-level mutable caching state.
- **Total function:** no throw paths, no I/O, no clock/env/network/randomness. Determinism proven by the 100-fixture property tier.
- **Shared-layer purity:** file imports NOTHING (`rg "^import|from \""` → 0 hits) — the ESLint `no-restricted-imports` ban on `@/backend|frontend|app` trivially holds.

### Decisions & rationale

1. **Test placement — beside the source** (`shared/lib/mask-full-name.test.ts`): Task 1.1 had not yet landed when this task started (its file appeared mid-session from a concurrent agent). Discovered precedent: shared-layer unit tests live beside sources (`shared/locale/errors-namespace.parity.test.ts`, `shared/locale/applicant-namespace.parity.test.ts`); sibling Task 1.1 independently chose the same convention (`shared/constants/handshake-code.constants.test.ts` — observed during this session). `bunfig.toml` has a single `[test]` section with no path/root restriction (standard preloads apply to all suites), so `shared/lib/` test files are fully included by `bun test <path>`. Convention confirmed twice.
2. **Branch-free first-segment extraction:** `const [leadingSegment] = segmenter.segment(part);` — a for-of with an unconditional first-iteration `return` would trip `sonarjs/no-one-iteration-loop` (sonarjs recommended is enabled in `eslint.config.mjs:64`), and any "defensive" unreachable return after such a loop would break 100% statement coverage. Destructuring has neither problem and is total for the guaranteed-non-empty parts.
3. **Non-empty-parts invariant (why no defensive empty checks):** a trimmed, non-empty string split on `/\s+/u` can never yield empty parts (no leading/trailing/adjacent separators possible after trim), so `firstGrapheme` always receives a non-empty string; both extraction paths then always return a string. The invariant is documented in the source JSDoc — this is what makes the function total WITHOUT unreachable defensive branches that would be uncoverable.
4. **Fallback-branch test mechanics:** `Reflect.deleteProperty(Intl, "Segmenter")` + `try/finally` restore via `Object.defineProperty` with the descriptor's real shape (`{ value, writable: true, configurable: true, enumerable: false }` — verified empirically). Plain assignment restore is impossible: the TS lib types mark `Intl.Segmenter` read-only for assignment (tsgo `TS2540`). Post-finally guards assert the global surface is restored AND the segmenter path is live again. The two paths are BEHAVIORALLY distinguished: `"e\u0301l"` → `"e\u0301***"` (segmenter keeps base+combining as one cluster) vs `"e***"` (fallback drops the combining mark) — different observable outputs prove which arm executed.
5. **Constants module-private, not exported:** no consumer needs them beyond this module (the service consumes `maskFullName`); the repo's dead-code rule forbids unused exports. Both constants are defined exactly once at the top of the file — the only programmatic `"***"` occurrences (plus one JSDoc example line).
6. **Tier-4 property corpus:** seeded xorshift32 (reproducible), 100 fixtures, multi-grapheme parts only. Rationale (documented in the test header): the leading grapheme of each part is disclosed BY DESIGN, so a single-grapheme input trivially appears inside its own masked part — the "never contains the full original" property is asserted over multi-grapheme originals where it is universally true and meaningful. Complementary explicit tests cover single-grapheme disclosure (`"ع"` → `"ع***"`).
7. **Mask-shaped inputs:** `maskFullName("x***") === "x***"` is a COINCIDENCE of shape (the output's asterisks are the fixed cluster, not the input's remainder — which was dropped); tested alongside `"xy***" → "x***"` proving the remainder never survives.

## 8. Residual Risks

1. **Cross-runtime fallback fidelity:** on a runtime WITHOUT `Intl.Segmenter`, a decomposed leading cluster (`e` + U+0301) masks as the bare base code point (`"e***"`) instead of the full cluster (`"e\u0301***"`) — different leading-grapheme fidelity across environments, but still deterministic PER runtime and never throwing. Every runtime this repo targets (bun, modern browsers, Node ≥16) ships `Intl.Segmenter`, so the fallback is a safety net rather than an active path.
2. **Default-locale argument:** `Intl.Segmenter(undefined, …)` uses the runtime default locale. Grapheme-cluster segmentation (UAX #29 extended grapheme clusters) has no locale tailoring in practice (unlike word/sentence/line granularity), so locale-independence holds; recorded as a theoretical caveat only.
3. **Part-count disclosure:** the number of name parts is visible in the mask (one cluster per part). This is inherent to the mandated per-part design ("first grapheme of each whitespace-separated part"), not a leak beyond it.
4. **No native bun branch metric:** branch-coverage evidence is structural + behavioral + line-hit based (§4.2). If the toolchain later gains a branch metric, re-verification is a one-command follow-up.
5. **Mask-shaped coincidences:** inputs like `"x***"` mask to themselves by coincidence (fixed cluster re-appended after the dropped remainder); no remainder information is disclosed — explicitly tested and documented to preempt future security-review questions.
