### 1.5 `test/preload/apollo-dev-flag.ts` (NEW) + `bunfig.toml` (MODIFIED)

**Rationale:** Apollo's default (non-bundler) build resolves its internal `__DEV__` from `globalThis.__DEV__ === true` at module-load time; Bun does not set it, so under `bun test` Apollo otherwise behaves like a production build and the "Cache data may be lost" (invariant 118) diagnostics are structurally inert — every zero-warning assertion would be vacuously green. The preload sets the flag via `Reflect.set(globalThis, "__DEV__", true)` before any test file can import `@apollo/client`, and exports `apolloDevModePreloaded = true` so suites can value-import the marker (bare side-effect imports are lint-forbidden). Registered as the LAST `[test]` preload in `bunfig.toml` (after `graphql-interop.ts`): process-wide by design, but side-effect-safe for unrelated suites (dev mode only unlocks diagnostics; `console.*` stays no-op'd by `logger-mock.ts`). Both warning-asserting suites re-assert the marker in-file and end with a dev-mode CANARY that fails loudly if the flag ever stops capturing.
