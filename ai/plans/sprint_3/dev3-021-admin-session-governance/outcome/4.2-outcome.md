## 3. needsAttention surfacing decision (the mechanism 5.x must select)

**Decision: a server-derived `needsAttention: Boolean!` field ON the canonical `Session` object** (`backend/graphql/pothos/classes/session.pothos.ts`, declaration position after the DEV3-005 dispute surface, before the row timestamps; SDL pins recalibrated in `backend/graphql/test/session-sdl.test.ts` accordingly). Exact mechanism:

- The **admin DIRECTORY read (`listAll`) is the ONLY producer**: its per-row projection stamps `needsAttention = true` when the row is **disputed OR scheduled with a lapsed confirmation deadline**, else `false`. The badge is **computed per request, NEVER persisted** (suite pins the frozen-clock flip: lapsed deadline → `true` under `setSystemTime`, back to `false` after clock restore).
- The `Session.needsAttention` resolver is a guarded absent-producer default: if the parent row carries no `needsAttention` member (every participant read, and the admin DETAIL read, which returns the plain canonical row), it resolves to `false`. So the `adminSession` detail **always answers `needsAttention: false`** (recorded constraint — the badge is a directory/list-styling projection only).
- It is **presentation-only styling input, never an authorization signal** (documented in both the object and query file headers).

**5.x consequence:** both shared documents must select `needsAttention` on `Session` selections (and `id` on every object per the contract convention); on `AdminSessionsQueryDocument` directory rows it may be `true`, on `AdminSessionQueryDocument` detail it is always `false`.
