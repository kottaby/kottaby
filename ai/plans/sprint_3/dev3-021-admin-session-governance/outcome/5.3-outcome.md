- **Metadata title-only (deliberate):** the exemplar `disputes/page.tsx` is also title-only, and `AdminSessionGovernanceLabels` (the 5.2 namespace, 76 keys) exposes `pageTitle` but NO `metaTitle`/`metaDescription`/`pageSubtitle` key. Adding a metadata-description key here would be untasked locale churn — page heading + metadata share `pageTitle`, and the 5.2 outcome pinned "zero new keys". `pageTitle` resolves to `"Session governance"` (en) / `"حوكمة الجلسات"` (ar).
- **Guard semantics (docblock-documented):** anonymous → `/login?redirect=/admin/session-governance`; non-admin role → caller's own role dashboard via `roleDashboardPath` (never the bare `/dashboard` dispatcher — the preview-gateway loop fix); admin → container. The guard is the ONLY authorization boundary; the container performs no role logic (5.2 contract §9), and the backend operations fail any non-admin into the canonical FORBIDDEN.
- **No props cross the server→client boundary** — the container resolves every label client-side through `useAppTranslation(AdminSessionGovernance)` (the users-page docblock rationale: namespace carries interpolation closures that cannot cross serialization).
