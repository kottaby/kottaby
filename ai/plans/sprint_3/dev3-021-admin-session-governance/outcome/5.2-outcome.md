Contract invariants: children are presentational-only (dialog/drawer/menu state lives in the Container); labels flow DOWN as typed `AdminSessionGovernanceLabels`/`SessionsLabels` objects (children never call the namespace registry except the Container and Drawer, which consume `useAppTranslation`/`useAppLocale` directly); every mutation payload is the uniform `Session!` shape so Apollo cache normalization converges directory rows by `id` with no refetch; `AdminSessionDetailDrawer` receives `detail === null` (browse read absence → "row does not exist" body, NOT an error surface); container classifies mutation errors through `extractErrorCode` + `normalizeGraphQLErrorCode` into race (close dialog + error snackbar) vs retryable (keep dialog open + snackbar) — the server `message` is never echoed.

## 4. Eligibility gating (D-03 matrix) — where and how

Implemented as module-scope `Record<string, true>` lookup tables keyed by `SessionStatus` (no stringly comparisons):

- `AdminSessionRow.tsx`: `TIMING_MUTABLE_STATUSES = { scheduled, started }` → gates `actionReschedule`/`actionCancel`; `REASSIGN_ELIGIBLE_STATUSES = { scheduled }` → `actionReassign`; `JOIN_ELIGIBLE_STATUSES = { started }` → `actionJoin` (join also lives in the drawer, below). INELIGIBLE actions render **disabled with an explanatory tooltip** (translated `*DisabledHint` keys) instead of disappearing — the affordance stays discoverable and the operator learns the rule. View-details is always enabled.
- `AdminSessionDetailDrawer.tsx`: `JOIN_OBSERVABLE_STATUSES = { started }` controls `joinVisible` — the join banner mounts only for live rows.
- Mirrors the backend matrix exactly: reschedule/cancel ⇒ `scheduled|started`; reassign ⇒ `scheduled` only; join ⇒ `started` only.

## 6. Plan-relevant implementations

- **needsAttention badge rendering** — two surfaces: (a) `AdminSessionRow` renders a warning-palette `Chip` (`WarningOutlined`, translated `needsAttentionLabel` tooltip) only when the server-derived `row.needsAttention` is `true` — directory-only data, presentation-only, never an authorization signal; (b) `AdminSessionGovernanceChrome` renders the needs-attention summary card in the warning tone (`SummaryCard count label tone="warning"`), counting loaded rows with the flag.
- **Responsive strategy (detail drawer, one body — no triplication)** — ≥md (`isDesktop`): side `Drawer` `anchor="right"` with rounded inline-end paper (MUI flips horizontal anchors under RTL, so `right` stays LOGICAL — the Drawer docblock + sibling `UserDetailHero` precedent); sm…md: full-screen `Dialog` (`aria-labelledby`); <sm: temporary bottom `Drawer` (`maxHeight: 92vh`). The same `header`/`body` ReactNodes render into whichever host matches the breakpoint (`useMediaQuery` + `useTheme`).
- **RTL logical props** — no physical sides in layout: `textAlign: "start"`, logical flex/grid alignment, `borderTopLeftRadius`-style logical radii on the end-anchored panel; kebab `Menu` uses MUI's viewport-clamped default origins (the `end` origin value is not a valid MUI origin type, and the app sets document `dir` without `theme.direction` — the NotificationDrawer precedent — so physical left/right were deliberately avoided); the side Drawer relies on MUI's direction-aware anchor flip.
- **Cancel idempotency (REQ-023 replay dedupe)** — the Container mints ONE `crypto.randomUUID()` when the cancel dialog OPENS and sends it per submit via the Apollo context header `x-idempotency-key` (`context: { headers: { "x-idempotency-key": cancelKeyRef.current } }` — the broadcasts compose-send precedent). The key rotates ONLY on mutation success, so a failed/retried submit keeps the same claim; the dialog itself only forwards the optional reason.
