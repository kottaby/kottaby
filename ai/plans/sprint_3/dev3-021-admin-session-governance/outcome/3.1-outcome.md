## 11. Mid-point R1 fix addendum (task midpoint-R1-fix-A)

Mid-point review wave R1 findings against this module, all resolved on `feat/dev3-021-admin-session-governance`:

1. **[MEDIUM] Unpointed idempotency claim defeats the mis-point classification** (`session-admin-governance.helpers.ts`) — when a keyed cancel's guarded UPDATE misses because the row is already cancelled, the replay arm committed the claim with its `session_id` pointer still NULL (`updateClaimSessionId` ran only on the success path), so a later retry with that key against a DIFFERENT cancelled session bypassed the `claim.sessionId !== sessionId` mis-point guard and resolved as a legitimate replay. **Fix (review direction (a), mirroring the booking flow's claim-backfill discipline):** `resolveCancelledReplayOrConflict` now receives the claim row (replacing the `claimExists` boolean) and the replay arm backfills the claim's session pointer in the SAME transaction — a committed claim always names the session it resolved against, so the existing mis-point guard is airtight and replay semantics are preserved for the SAME session only. Regression test added to this suite: *"a replay-arm claim points at the session it replayed against: the same key on a DIFFERENT cancelled session is the mis-point conflict, the same session still replays"* (replay response on A → claim pointer invariant asserted directly → different-session retry on B is `ConflictError("SESSION_INVALID_TRANSITION")` with zero writes → same-session re-replay on A is still the write-free replay).
2. **[LOW]** `SESSION_STARTED_STATUS` was re-declared locally; the byte-identical widening from `session-lifecycle.guards.ts` is now imported (the hub imports it from the guards module directly as well — one widening vocabulary, no second declaration).
3. **[LOW]** `countAdminDirectory` + `listAdminDirectory` un-exported from `session.repository.helpers.ts` (module-internal, consumed only by `listAdminDirectoryPage`; the repo-wide `export async function` source pin is unaffected — they were export-block names).
