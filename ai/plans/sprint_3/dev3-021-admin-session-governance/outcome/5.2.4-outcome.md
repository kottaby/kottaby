## 3. Root cause + fix — Container branch 5 (filter re-key determinism)

- **Symptom:** branch 5 ("status filter APPLY re-keys the query → filtered-empty copy; RESET restores it") failed non-deterministically when driving the MUI status `<Select>`.
- **Root cause:** MUI v9 renders `<Select data-testid=…>` such that the **`data-testid` lands on the outer FormControl wrapper while the open/click handler lives on the INNER `role="combobox"` SelectInput display div** — firing events at the testid target hits the wrapper and never opens the listbox, so the select-value fireEvent misses (broadcast-suite precedent documented this first).
- **Fix (test-side only, zero component changes):** resolve the combobox by accessible name and drive it with the mouseDown open gesture — `fireEvent.mouseDown(screen.getByRole("combobox", { name: t.filterStatusLabel }))` — per the broadcast-suite convention; the accessible name keeps the query locale-scoped (ar + en) and unique on the surface. Committed as `dfdf333` ("fix filter re-key test determinism").
