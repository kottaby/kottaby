## 4. Exact exported surface (carry-forward for tasks 2.1 / 3.1 / 4.1 / 4.2 / 4.3)

All exported from `@/backend/types` via `backend/types/classes` (import root: `@/backend/types`).

**Types:**
- `AdminSessionListFilterInput` — `{ teacherUserId?, studentUserId?, type?: SessionType, status?: SessionStatus, dateFrom?: Date, dateTo?: Date, page?, pageSize? }` (all optional, all `readonly`)
- `AdminSessionRescheduleInput` — `{ sessionId: number, startedAt: Date, endedAt: Date }`
- `AdminSessionCancelInput` — `{ sessionId: number, reason?: string }` (≤2000 chars enforced by schema)
- `AdminSessionReassignInput` — `{ sessionId: number, newTeacherUserId: number }`
- `AdminSessionJoinInput` — `{ sessionId: number }`
- `AdminSessionRowReturnType` — `SessionReturnType & { readonly needsAttention: boolean }` (intersection-extension convention; `SessionReturnType` = `typeof session.$inferSelect`, so timestamps are `Date | null`)
- `AdminSessionDetail` — `SessionReturnType | null` (browse read: absent id → `null`, never a thrown NOT_FOUND, never `undefined`)

**Zod schemas (same file, exported — v4 API):**
- `AdminSessionListFilterInputSchema` — object schema + window-pairing refine (`dateFrom <= dateTo`; inverted rejected, zero-width accepted)
- `AdminSessionRescheduleInputSchema` — object schema + `startedAt < endedAt` refine (equality rejected)
- `AdminSessionCancelInputSchema`
- `AdminSessionReassignInputSchema`
- `AdminSessionJoinInputSchema`

**Schema semantics (binding for downstream consumers):**
- Every id (`sessionId`, `teacherUserId`, `studentUserId`, `newTeacherUserId`): `z.number().int().positive()` — in zod v4 `.int()` accepts ONLY safe-integer-range numbers, which is exactly the `isPositiveSafeSessionId` vocabulary (`session-lifecycle.guards.ts:111/123`: `Number.isSafeInteger && > 0`). NaN / fractional / negative / zero / strings / `Infinity` all reject at the boundary.
- `page`: integer ≥ 1. `pageSize`: integer 1..50 (`normalizeAdminListBounds` precedent, guards:206 — clamp/default normalization remains a service concern for ABSENT members; out-of-window PRESENT members reject here).
- `reason`: optional string, max 2000 (audit-details width). No schema-level trim — whitespace-only → "no reason" normalization stays in the service (mirrors `normalizeOptionalReasonText` semantics, guards:155).
- Dates: `z.date()` — operates on post-DateTime-scalar `Date` instances, NOT transport strings (GraphQL `DateTime` scalar at `backend/graphql/pothos/shared/scalar.pothos.ts:30` parses ISO strings first). A raw string payload rejects.
- Object schemas use zod default strip mode → unknown client keys are silently dropped (BOPLA REQ-031): extra fields can never reach a repository write. Proven by dedicated tests.
- Enum members: `z.enum(SessionType)` / `z.enum(SessionStatus)` — closed vocabularies; enums imported as VALUE imports (runtime requirement of `z.enum`) and double as the type vocabulary.
- NO custom zod messages: schemas carry zero hardcoded copy; downstream (4.x) maps `safeParse` failure `issues` to localized `errorsTranslations` entries (task 1.2's `session` namespace).
