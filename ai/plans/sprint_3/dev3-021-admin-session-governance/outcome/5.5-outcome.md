**Verbatim blocker (root cause):** `test/scripts/run-server-tests.ts:579-582` —

```
  if (isPgliteProvider) {
    state.lastServerAction = "PGlite mode — skipping warm-server spawn (GraphQL suite skipped).";
    return;
  }
```

The runner **skips the warm-server spawn entirely when `DB_PROVIDER=pglite`**. This sandbox has no native Postgres daemon (apt restricted; the repo sanctions pglite for sandbox dev — see worklog setup entry and `outcome/0.1-baseline-outcome.md`), so `isPgliteProvider` is true, no server is spawned on port 3066, and the e2e spec's first wire call gets `ConnectionRefused` (`code: "ConnectionRefused"` at `admin-session-governance.e2e.test.ts:130` ← `loginCookie`). In CI, e2e runs with a real Postgres `DATABASE_URL` (see `.env.test.ci` materialization docs), so the spawn path activates there. This is a **pre-existing runner design decision**, not a defect of this plan's spec; fixing the runner to spawn under pglite is out of this ticket's scope.
