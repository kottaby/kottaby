## Summary

NEW `backend/graphql/pothos/teachers/evaluation.pothos.ts` defines the single canonical `Evaluation` GraphQL object over the canonical `EvaluationReturnType` from `@/backend/types`, plus the string-named `SubmitTeacherEvaluationInput` Pothos input. Field order and nullability mirror the committed service return shape exactly: `id` first (Apollo cache normalization, `ID!` via `t.exposeID`), `evaluatedId`/`evaluatorId` as non-nullable `Int!` (`t.exposeInt`), `sessionId` nullable `Int` (standalone applicant rows + session-deletion SET NULL), `score` nullable `Int` (nullable column), `createdAt` non-nullable `DateTime!` (NOT NULL column; the shared `DateTime` scalar from `shared/scalar.pothos.ts`). The input exposes exactly one client-owned field, `rating: Int!` (`t.int({ required: true })`), via `gqlSchemaBuilder.inputType("SubmitTeacherEvaluationInput", …)` — deliberately NOT `inputRef`, so the wire input's nullability never couples to the backend type's exact shape. NO local type declarations, NO enum literals (nothing enum-typed on this surface), NO inline logic — every field is a structural passthrough. Registration is transitive: the teachers domain is deliberately absent from the top Pothos barrel; both types register when the 3.2/3.3 resolver modules import them through the `gqlSchema.ts` side-effect chain (exact `pothos/teachers/applicant.pothos.ts` convention).
