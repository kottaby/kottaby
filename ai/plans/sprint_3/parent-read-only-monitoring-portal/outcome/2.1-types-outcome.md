## Notes on convention adherence

- The `import type { LinkStatus }` pattern in `parent-link-request.types.ts:2-8` documents that Biome `lint/style/useImportType` auto-normalizes value-imports to `import type` when the symbol is used only in type positions, and that runtime consumers (the `isLinkStatus` fail-closed guard, the service-layer status transitions) keep their own value imports. The same convention applies here: `SessionStatus` and `SurahJuzRef` are used ONLY in interface-member type positions in this file, so `import type` is both correct and Biome-stable. The future read-mapping helper (task 2.4 service layer) and any `isSessionStatus` / `isSurahJuzRef` guards will import these enums as VALUES from `@/backend/enum/...` in their own files.
- The page-window honesty contract (`page` / `pageSize` echo effective values, out-of-range page yields empty `items` next to true `totalCount`) is identical to `SessionPageReturnType` (`backend/types/classes/session.types.ts:58-63`) — the same contract parents expect on every paginated surface.
- The composite `ParentChildProgressReturnType` (carrying the gated `child` echo + progress + latest positions in one payload) is the deliberate single-payload design that makes `ParentChildOverviewReturnType` unnecessary (plan §2.3 explicit exclusion — fewer BOLA seams).
