## Summary

This is the INTERIM outcome for task 5.3a — the split part 1 of task 5.3
covering the two container components + the components-only barrel. Task
5.3b (the five tab components) writes the final `5.3-views-outcome.md`;
this file documents only the container + barrel surface.

The three files in scope (all in `frontend/views/parent/monitoring/`):

1. `ParentChildrenRootContainer.tsx` — portal root client surface mounted
   at `/parent/children`. Owns the `useQuery(myLinkedChildrenQueryDocument)`
   (zero-arg — caller identity IS the read scope) and the CLIENT-SIDE
   auto-select-first `useEffect` (PINNED §4.3 — never server-side).
   Resolves a missing `?student=` URL param by `router.replace`-ing to
   `/parent/children/<firstChildId>` once the query resolves. Zero linked
   children renders the localized `IconCircleEmptyState` + handshake CTA
   button. ≥1 renders the portal header + count + list of clickable
   `ChildCard`s. Render state matrix: loading → skeleton; FORBIDDEN /
   UNAUTHORIZED → `PermissionDeniedFallback`; other errors →
   `ErrorRetryAlert`; data-empty → `IconCircleEmptyState` + CTA; data →
   list.

2. `ParentChildDetailContainer.tsx` — per-child detail client surface
   mounted at `/parent/children/<studentId>`. Owns the MUI `Tabs` strip
   (writes `?tab=` via `router.replace` — no history churn per tab click)
   and the `ChildSwitcher` (writes the path segment via `router.push` —
   back-button support). Forwards `?session=` deep-link (DEV1-017 R-I)
   to the Reports tab. URL IS the state (D6): the active tab, active
   student, and deep-link session are ALL derived from URL props on
   every render — ZERO `useState` for any of them. ALL per-tab
   `useQuery` hooks live in the tab components (task 5.3b) and re-key on
   `studentId` (Apollo cache isolation — rows never leak across
   children).

3. `index.ts` — components-only barrel re-exporting the two containers +
   the five tab components. Presentational parts (`*.parts.tsx`) and the
   locale-neutral display helpers (`parentMonitoringDisplay.ts`) stay
   deep-imported — they are not part of the public surface.

## Tab-handoff approach

The task description offered two options for handling the not-yet-existing
tab components: (a) lazy/dynamic import, or (b) minimal placeholder tab
stubs that 5.3b replaces.

**Chosen approach: direct static import.** At execution time, all five
tab components (`AttendanceTab.tsx`, `ReportsTab.tsx`, `HomeworkTab.tsx`,
`EvaluationsTab.tsx`, `ProgressTab.tsx`) ALREADY EXIST in the working
tree as untracked files from a prior partial attempt. They compile
cleanly against the task-5.1 documents (verified via `bun tsgo` exit 0
on the whole module). Rather than introduce lazy/dynamic import
indirection (which would split the bundle unnecessarily and complicate
the SSR story) or stub-and-replace placeholders (which would create a
churn risk), the container imports the existing tab components via
direct static imports. Task 5.3b will finalize / verify the five tab
implementations; the container's import surface is stable either way.

This is the cleanest compiling approach, and the barrel's
`export * from "./<Tab>"` lines remain valid.

## Render state matrix (uniform across both containers)

| State | Trigger | Rendered surface |
|---|---|---|
| `loading` | `useQuery` in flight, no snapshot yet | Skeleton region (`component="output" aria-busy`) — root container renders `ChildrenListSkeleton`; detail container renders header + switcher skeleton (the active tab owns its own loading state) |
| `FORBIDDEN` / `UNAUTHORIZED` | `extractErrorCode(error)` returns one of these codes | `PermissionDeniedFallback` (constant-shape denial — the server's raw `message` is NEVER rendered) |
| Other errors | `error !== undefined` and code is not FORBIDDEN/UNAUTHORIZED | `ErrorRetryAlert` with `errors.internalServerError` title + `common.retry` button + `loadErrorBody` body |
| Data-empty (root only) | Snapshot resolved with zero linked children | `IconCircleEmptyState` with `GroupOutlined` icon + handshake CTA button deep-linking to `/parent/handshake` |
| Data | Snapshot resolved with ≥1 child (root) / linked-children list resolved (detail) | Root: portal header + count + clickable `ChildCard` grid. Detail: header + `ChildSwitcher` + MUI Tabs + active tab content |

## URL-param contract (D6 — URL IS the state)

| URL surface | Owner | Write mechanism | Preserves |
|---|---|---|---|
| `/parent/children` (root, no `?student=`) | `ParentChildrenRootContainer` | `useEffect` → `router.replace('/parent/children/<firstChildId>')` (auto-select-first, PINNED §4.3 — client-side, never server-side) | — |
| `/parent/children?student=<id>` (root, with param) | `ParentChildrenRootContainer` | Renders the list view (param signals explicit list browsing) | — |
| `/parent/children/<studentId>` (detail path segment) | Server page (task 5.2) validates the segment; `ParentChildDetailContainer` consumes the coerced `number` | Child switcher → `router.push('/parent/children/<newId>?tab=<current>&session=<current>')` (back-button support) | `?tab=`, `?session=` |
| `?tab=<attendance\|reports\|homework\|evaluations\|progress>` | `ParentChildDetailContainer` MUI `Tabs` `onChange` → `router.replace` (no history churn per tab click) | `?session=` |
| `?session=<id>` (Reports deep-link, DEV1-017 R-I) | Server page forwards as prop; `ParentChildDetailContainer` parses to `number \| null` (NaN-safe) and forwards to `ReportsTab` → `ReportRow.scrollIntoView` | — |

**No parallel local state:** the tab index, the active student, and the
deep-link session are ALL derived from the URL props on every render —
no `useState` for any of them (verified by grep: `useState` → ZERO hits
on either container file). The only `useEffect` is the root container's
auto-select-first navigation.
