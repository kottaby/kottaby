## Summary

Completed the `frontend/views/parent/monitoring/` module — the client
view layer of the parent read-only monitoring portal. The module ships
seven public components (two containers + five tabs) plus their
co-located presentational parts, the locale-neutral display helpers,
and a components-only barrel — 16 files in total. Every rendered value
flows from a real `useQuery` hook backed by the five task-5.1 documents
— zero hardcoded fixtures, zero mock state, zero mutation affordances
(REQ-023.3).

The state matrix is uniform across all five tabs and both containers:
`loading` → skeleton (`component="output" aria-busy`); `FORBIDDEN` /
`UNAUTHORIZED` (classified via `extractErrorCode`) →
`PermissionDeniedFallback` (the server's raw `message` is NEVER
rendered); other errors → `ErrorRetryAlert` (retry refetches);
data-empty → localized `IconCircleEmptyState`; data → rows. Null
ratings render "not rated yet" (never `0`); null homework track blocks
render "none assigned"; null progress positions render the
"no recorded position" inline copy.

URL-is-the-state: the child switcher navigates to
`/parent/children/<newId>` (path segment, `router.push` for back-button
support); MUI `Tabs` writes `?tab=` via `router.replace` (no history
churn per tab click); the `?session=` deep-link is forwarded to the
Reports tab which scrolls the matching session row into view (the
deep-link target for session-scoped notifications). No Zustand, no
parallel local copy of the URL state — the root container's single
`useEffect` reads the resolved `myLinkedChildren` payload and
`router.replace`s to the first child's detail URL when the root page is
hit with no `?student=` param (client-side resolution, never
server-side).

## State matrix per tab (5.3b audit — uniform across all five tabs)

Each tab component renders exactly one of five mutually-exclusive
branches per query lifecycle state. The audit verified every branch is
reachable and terminates at the correct surface (no dead arms):

| State | Trigger | Rendered surface | Verified in |
|---|---|---|---|
| `loading` | `useQuery` in flight, no snapshot yet (`rows === undefined` and `error === undefined`) | Skeleton region (`aria-busy="true"`, stable string keys avoiding `noArrayIndexKey`) | All 5 tabs |
| `FORBIDDEN` / `UNAUTHORIZED` | `extractErrorCode(error)` returns one of these codes | `PermissionDeniedFallback` (constant-shape denial — the server's raw `message` is NEVER rendered) | All 5 tabs + both containers |
| Other errors | `error !== undefined` and code is not FORBIDDEN/UNAUTHORIZED | `ErrorRetryAlert` with `errors.internalServerError` title + `common.retry` button + `loadErrorBody` body | All 5 tabs + root container |
| Data-empty | Snapshot resolved with zero rows (or, for Progress: `progressRowCount === 0 && both positions null`) | `IconCircleEmptyState` with localized title + body per surface | All 5 tabs + root container |
| Data | Snapshot resolved with ≥1 row (or, for Progress: non-empty payload) | Per-row `Card`s in a `component="output"` grid (`display: "grid"`, `gap: 2`) | All 5 tabs |

**Error classification approach**: each tab calls
`extractErrorCode(error)` and compares the returned code string
directly to `"FORBIDDEN"` / `"UNAUTHORIZED"`. This is the simpler
equivalent of the `mapGraphQLErrorByCode` "permission-fallback" kind
check (documented in 5.3a outcome) — the portal has no poll interval,
so there is no sticky-denial snapshotless re-attempt window to defend
against. Both routes terminate at `PermissionDeniedFallback` for the
FORBIDDEN/UNAUTHORIZED subset.

## URL-param contract (URL IS the state)

| URL surface | Owner | Write mechanism | Preserves |
|---|---|---|---|
| `/parent/children` (root, no `?student=`) | `ParentChildrenRootContainer` | `useEffect` → `router.replace('/parent/children/<firstChildId>')` (auto-select-first — client-side, never server-side) | — |
| `/parent/children?student=<id>` (root, with param) | `ParentChildrenRootContainer` | Renders the list view (param signals explicit list browsing) | — |
| `/parent/children/<studentId>` (detail path segment) | Server page (task 5.2) validates the segment; `ParentChildDetailContainer` consumes the coerced `number` | Child switcher → `router.push('/parent/children/<newId>?tab=<current>&session=<current>')` (back-button support) | `?tab=`, `?session=` |
| `?tab=<attendance\|reports\|homework\|evaluations\|progress>` | `ParentChildDetailContainer` MUI `Tabs` `onChange` → `router.replace` (no history churn per tab click) | `?session=` |
| `?session=<id>` (Reports deep-link) | Server page forwards as prop; `ParentChildDetailContainer` parses to `number \| null` (NaN-safe via `Number.isNaN` check at `ParentChildDetailContainer.tsx:98-99`) and forwards to `ReportsTab` → `ReportRow.scrollIntoView` | — |

**No parallel local state:** the tab index, the active student, and
the deep-link session are ALL derived from the URL props on every
render — no `useState` for any of them (verified by grep: `useState`
on the 16-file module → ZERO hits). The only `useEffect`s are:
1. The root container's auto-select-first navigation (idempotent
   `router.replace` to a deterministic URL).
2. The `ReportRow`'s scroll-into-view when `isDeepLinkTarget` becomes
   true (bounded to a single row's ref).

## Deep-link `?session=` scroll-into-view (R-I for session-scoped notifications)

The flow is wired end-to-end:

1. URL: `/parent/children/<id>?tab=reports&session=<sessionId>`
2. Server page (task 5.2) extracts `session` as a string and forwards
   it as a plain prop.
3. `ParentChildDetailContainer.tsx:98-99` NaN-safe parsing:
   `const sessionNumber = props.session === null ? null : Number(props.session);`
   `const sessionArg = sessionNumber !== null && Number.isNaN(sessionNumber) ? null : sessionNumber;`
4. `ParentChildDetailContainer.tsx:112` forwards to `<ReportsTab session={sessionArg} />`.
5. `ReportsTab.tsx:95` passes `deepLinkSessionId={props.session}` to
   each `ReportRow`.
6. `ReportsTab.parts.tsx:58` computes `isDeepLinkTarget = deepLinkSessionId !== null && deepLinkSessionId === row.sessionId`.
7. `ReportsTab.parts.tsx:60-64` `useEffect` calls
   `rowRef.current.scrollIntoView({ behavior: "smooth", block: "center" })`
   when `isDeepLinkTarget && rowRef.current !== null`.
8. `ReportsTab.parts.tsx:76` `aria-current="true"` on the deep-link
   target row for accessibility (otherwise `undefined`).

The matching row also gets a primary-color 2px border
(`borderColor: isDeepLinkTarget ? theme.palette.primary.main : theme.palette.border.main`)
so the visual focus matches the scroll focus.
