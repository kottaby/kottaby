## Summary

Implemented the full `parentMonitoring` i18n namespace ceremony — the
compile-time-typed locale namespace backing every user-facing string on
the parent read-only monitoring portal. The ceremony follows the
`parentLink` sibling precedent verbatim (the closest sibling namespace —
also parent-domain, also en/ar parity-tested).

existing-file updates (type registry, namespace registry, namespace
barrel, en/ar aggregate bundles), one new namespace handle + barrel, and
one new parity test. The `ParentMonitoringLabels` interface exposes
62 typed slots covering every portal surface (portal root, child
switcher, detail page header, the five tabs, Jadid/Madi track
vocabulary, per-surface empty states, loading/error scaffolding).

slots so each locale owns its own plural-class branching.

calls). Sibling parity tests (`parentLink`, `handshakeCode`,
`notifications`, `analytics`) and the locale server test all still pass —
zero regressions across the shared locale layer.

## Cross-file dependencies discovered

- **`shared/locale/types/message.ts`** is the load-bearing step everyone
  forgets (per `plan-review-R1.md` lesson #3) — adding
  `parentMonitoringTranslations: ParentMonitoringLabels;` to the
  `Translations` interface is REQUIRED before the namespace handle
  compiles (the `defineNamespace` getter references
  `translations.parentMonitoringTranslations`).
- **`shared/locale/en/messages.ts` + `shared/locale/ar/messages.ts`**
  must BOTH be updated in lockstep with the `Translations` interface
  change — otherwise `bun tsgo` fails with "Property
  'parentMonitoringTranslations' is missing in type ...".
- **`shared/locale/namespaces/index.ts`** barrel must add the
  `export * from "./parentMonitoring";` line — otherwise the parity
  test's `import { namespaces } from "@/shared/locale/namespaces/index";`
  fails (the registry.ts file imports each handle directly via
  `@/shared/locale/namespaces/<ns>`, but the consumer-facing barrel
  must re-export for top-level `@/shared/locale` imports).
- **No existing parity test auto-discovers namespaces.** Each namespace
  ships its own dedicated parity test file

  `parentMonitoring-namespace.parity.test.ts` was authored from
  scratch, mirroring the `parentLink` precedent (scaled to this
