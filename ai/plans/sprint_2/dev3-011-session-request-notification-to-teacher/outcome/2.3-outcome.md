### Deviations (2, both documented and test-pinned)

- **D1 — caller-tx union narrowing (A7 concretized).** Plan-§4.2's `return result;` cannot compile as written: `NotificationEngine.emitForUser` statically returns `NotificationReturnType | NotificationDeliveryReceipt`, the receipt is not assignable from the union, and `as` casts are prohibited (`no-unsafe-type-assertion`). Engine files are frozen by scope ruling, so narrowing must live in this module. A7's actual constraint — receipt returned verbatim, NEVER published, and the wrap-fallback moved OFF the caller-tx path — is realized by a structural `!("notifications" in result)` guard whose contractually-impossible branch throws a typed `DomainError("INTERNAL_SERVER_ERROR", tErrors.internalServerError)` (NOT the banned wrap, NOT a silent mask). The guard is provably testable: the service suite pins it via `spyOn(NotificationEngine, "emitForUser").mockResolvedValue(bareRow)` (Tier-3 test "caller-tx path rejects an engine contract breach"). No dead code, no coverage hole (the A2 lesson preserved).
- **D2 — int4 ceiling instead of `Number.MAX_SAFE_INTEGER` for the "valid shape, missing" boundary probe.** `session.id` is `integer` (int4, `generatedAlwaysAsIdentity`, `backend/db/schema/classes/session.ts:35`); binding `2^53-1` into `WHERE id = $1` would raise Postgres 22003 (range), never a miss. The probe therefore uses the column ceiling `2_147_483_647` (valid shape, guaranteed absent) → `SESSION_NOT_FOUND`. The unsafe-magnitude bucket (`2**53`, `MIN_SAFE_INTEGER`) remains in the pre-DB VALIDATION matrix, so the boundary intent is fully covered.
