## ⚠️ Key Decision — FLAT key, not a nested `notifications` group (plan-text adaptation)

The plan docs (`plan.md` §2.4(a), `tasks.md` 1.3) instruct adding `notifications: { notificationNotFound: string; }` **grouping**, with the directive *"match existing grouping style — check how other groups like sessionLifecycle are structured."* That check was performed against the codebase ground truth and **the premise is false**:

1. **No groups exist in `ErrorsLabels`.** The errors namespace is a FLAT machine-code → message map (21 keys pre-task; now 22). The interface's own header pins the convention: *"Keys are lowercase camelCase of the SCREAMING_SNAKE_CASE codes"* — `NOTIFICATION_NOT_FOUND` ↔ `notificationNotFound` is exactly that bijection (same as `APPLICANT_NOT_FOUND` ↔ `applicantNotFound`).
2. **`sessionLifecycle` does not exist in the codebase.** Repo-wide grep: it appears ONLY in the UNEXECUTED sprint_1 plan `ai/plans/sprint_1/dev3-005-.../` (specs/tasks/plan) — that plan has no `outcome/` directory and never landed. The referenced "existing grouping style" is unlanded plan vocabulary, not repo convention (same drift class as plan-review-R1 A4 "Translation enum" and A2 "extend existing repo").
3. **The binding precedent for this exact task archetype** — dev2-004 Task 1.3 (also REQ-051, most recent real extension of this namespace) — added its domain-scoped keys FLAT (`applicantNotFound`, `applicantCooldownActive`, `applicantStatusCorrupt`), with zero collateral file changes ("Zero other namespaces, zero frontend/backend files touched").
4. **The load-bearing contract assumes flat string leaves** — a nested group would BREAK all three of this task's own quality gates:
   - `GraphQLErrorAction.messageKey: keyof ErrorsLabels` (`frontend/providers/apollo/error-link.map.ts:168`) + its consumers `labels[action.messageKey]` (`error-link.map.test.ts:65`) and `t[action.messageKey]` (`GraphQLErrorSurfaceHost.tsx:156,246`) require every `ErrorsLabels` value to be a renderable string — a nested object value produces tsgo errors in **frontend files** (violating gate 2: `bun tsgo` 0 errors, and the rule "this task adds no consumers — just the keys").
   - `errors-namespace.parity.test.ts` "every value on BOTH maps is a non-empty localized string" (lines 85–94) and `applicant-namespace.parity.test.ts` "placeholder-name sets are IDENTICAL" (lines 121–133) iterate top-level keys and throw on non-string values — a nested group FAILS gate 3 instead of being auto-covered by it.

**Disposition (mirrors the plan-review A2/A4 adaptation pattern): codebase ground truth wins; flat key shipped; consumer path recorded below for downstream tasks.**
