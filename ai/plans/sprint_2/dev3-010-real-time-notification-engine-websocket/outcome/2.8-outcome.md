## 1. What Was Built

**The notification WebSocket sidecar** — a standalone `Bun.serve` process (the realtime lane; NOT an `app/api/**` route, so it never enters `ROUTE_INVENTORY` per plan §1.1 / D1):

- **`backend/ws/notification-ws-server.ts`** — `startNotificationWsServer(options)` boots a Bun-native WS server on `WS_HOST:WS_PORT` (port `0` = OS-assigned ephemeral; the handle reports the actual port):
  - **Handshake pipeline (FIXED order, REQ-022/033):** (0) non-WebSocket requests → HTTP `426`; (1) **Origin allowlist FIRST** (missing/non-allowlisted → HTTP `403`, socket never upgraded — the CSWSH defense); (2) per-IP token-bucket throttle (exhausted → policy close `4429`); (3) `access_token` httpOnly cookie via `parseCookies` + `AUTH_COOKIE_NAMES.accessToken` — the ONLY identity source; (4) `verifyAccessToken` (null on ANY failure → `4401`); (5) `userId` from the verified `sub` claim with a positive-safe-int re-assertion (the DEV2-001 verifier already coerces; defense in depth → `4401`); (6) `server.upgrade` — registration + both caps enforced atomically in `open()`.
  - **Bounded registry (REQ-023/046, the sanctioned exception):** `Map<connId, ConnState>` **per server instance** (stronger than the sanctioned module-level exception — concurrent test boots own isolated state); global cap → close `1013`; per-user cap → evict OLDEST with `4009` (insertion-order scan); app-owned 30s ping cadence (`sendPings: false` — Bun's internal auto-ping disabled so the contract is ours alone), 2 consecutive missed pongs → terminate; Bun `idleTimeout` derived ABOVE the liveness window so app-owned termination always fires first; graceful shutdown = unsubscribe → close every socket `1001` → bounded drain → forced stop.
  - **Throttle bucket:** bounded token bucket (capacity 5, 1 token / 2s sustained) over a **bounded tracked-IP map** (drop-oldest at 10 000) — the throttle structure itself cannot be grown unboundedly by spoofed-address handshakes.
  - **Subscriber wiring (2.5 BINDING):** the sidecar subscribes via `NotificationFanoutSubscriptionSource.subscribeFanout(listener)`; envelopes arrive ALREADY guard-validated by the transport (the Redis adapter's `parseFanoutEnvelope`); the listener routes `userIds` → registered socket sets and writes ONE projected frame per envelope — `JSON.stringify(projectFanoutPayload(payload))`, i.e. the `RealtimeNotificationPayload` allowlisted projection (REQ-021 shape; no recipient ids/PII ever cross the socket — the projection re-applies on egress so the allowlist holds on BOTH bus mediums, including the in-process tap which delivers un-serialized objects). A send failure on one socket logs one structured warn (`NOTIFICATION_WS_DELIVERY_DEGRADED`, connId+userId+errorName) and never disturbs the loop.
  - **Push-only protocol (REQ-034):** `message()` is empty — every client application frame is ignored; pong protocol frames reset the missed-pong counter; `maxPayloadLength` caps inbound frame size defensively (Bun's documented 16 MiB default, exported constant).
  - **Logging (REQ-037):** `logger` from `@/backend/lib/logger` exclusively; lifecycle logs carry `connId` + `userId` ONLY (+ policy `reason`/`code`/`errorName`); the throttle IP is a bucket key and is NEVER logged; the only address material in logs is the server's OWN listen host/port in the two process-lifecycle lines.
- **`scripts/start-notification-ws.ts`** — the `bun run ws` entry: config ONLY through the 1.5 env-seam getters (zero raw `process.env`), subscription source via the 2.5 selection factory (`resolveFanoutSubscriptionSource` — this task's additive factory export), Redis client owned and closed by the entry when the Redis bus is selected, SIGTERM/SIGINT handlers → graceful `1001` shutdown → `process.exit(0)` (exit 1 + structured error on boot/shutdown failure).
- **`backend/ws/index.ts`** — namespace barrel; **`backend/ws/AGENTS.md`** — layer rules (handshake order, close-code vocabulary, bounded-state contract, test conventions incl. the raw-TCP dead-peer technique).
- **`backend/services/notifications/realtime/fanout-transport.factory.ts`** — MODIFIED (additive): `resolveFanoutSubscriptionSource(options?)` — the symmetric subscribe-side selection over the SAME env-driven core (both adapters satisfy both port interfaces); the publish-side signature is byte-unchanged.

**Consumption rules (BINDING for Phase 3+ / the frontend client):**

- **Gateway topology (sandbox/dev):** the browser connects to the WS sidecar at **the sidecar's own origin** `ws://<WS_HOST>:<WS_PORT>` (dev default `ws://127.0.0.1:3001`) — NOT through the GraphQL gateway. `WS_ALLOWED_ORIGINS` defaults include `http://localhost:3000` and `http://127.0.0.1:3000` (the app origins the browser will send as `Origin`), so a same-machine dev browser handshake passes the allowlist. Behind the sandbox's Caddy/gateway topology a production deploy must add the public app origin to `WS_ALLOWED_ORIGINS` and route/proxy `wss://` to the sidecar port (D3 deferred item owns provisioning) — the sidecar itself needs no change.
- **Client handshake:** send the httpOnly `access_token` cookie (it rides automatically for same-site WS handshakes from the app origin) and a normal `Origin`; NO query-string token is ever honored. Treat the five policy closes as the complete error vocabulary: `4401` (re-auth required — abort retry), `4429` (back off), `4009` (this socket superseded by a newer one — the newest tab wins; the evicted tab's hook should back off per plan §4.5's flicker posture), `1013` (retry later), `1001` (server shutdown — reconnect with backoff + catch-up refetch).
- **Inbound frames:** the client sends NOTHING (pong/close are protocol-level); outbound frames are exactly `RealtimeNotificationPayload` JSON (`v: 1, kind: "notification, data: { id, type, title, body, relatedEntityType, relatedEntityId, createdAt }` — `createdAt` ISO string; `id` always present for cache dedupe).
- **Entry/runbook:** `bun run ws` (env: `WS_HOST`/`WS_PORT`/`WS_ALLOWED_ORIGINS`/caps via the 1.5 seam; transport via `NOTIFICATION_FANOUT_TRANSPORT` + `REDIS_URL`). Redis selected without a reachable Redis server → boot FAILS FAST with a structured error (a sidecar without a backplane serves nothing); Redis outage mid-run degrades inside the transport per REQ-045.
- **Do NOT** import the sidecar module from app code to "reach the registry" — the handle is process-local by design; cross-process fan-out goes through the transport port.

## 6. SEC — Security & Tenancy Audit (2.8.SEC)

- **CSWSH defense — Origin FIRST (REQ-022a/033):** the allowlist check is the FIRST handshake gate (before the throttle, before any identity material is read); missing or non-allowlisted Origin → HTTP 403 with the socket never upgraded (pinned: `opened=false` pre-upgrade rejection). Origins are matched after trim+lowercase against the frozen 1.5-registered allowlist (wildcards unreachable — 1.5 already proved).
- **No identity from URL/headers-payload (REQ-033):** grep evidence — the server module reads EXACTLY three headers: `upgrade` (protocol), `origin` (CSWSH), `cookie` (identity). ZERO `searchParams`/`url.search`/`new URL(`/querystring reads in the production namespace (query-token attempt pinned closed `4401` in Tier 4); inbound client frames are ignored by protocol so no first-frame identity can exist (REQ-034).
- **Fail-closed auth (REQ-022b):** `verifyAccessToken` returns `null` on ANY failure → `4401` — missing, tampered, expired, wrong-type, malformed all pin to the same code; garbage never 500s (the only non-2xx/upgrade paths are 426/403/429/401/400 — all before or at upgrade). `userId` derives EXCLUSIVELY from the verified token's `sub` (re-asserted positive-safe-int).
- **Throttle fail-closed (REQ-033):** bucket exhaustion closes `4429` (pinned with refill recovery); the bucket map itself is bounded (drop-oldest at `WS_THROTTLE_MAX_TRACKED_IPS`) so the throttle cannot be memory-DoSed; the IP is a key only — never logged.
- **Outbound payload allowlist (REQ-021):** the frame is `projectFanoutPayload(payload)` JSON ONLY — the 2.5 allowlisted projection re-applied at egress (single implementation, no duplication); runtime-smuggled properties (incl. a forged `userId`) provably never reach the wire (key-set + absence probes); no recipient email/phone/PII/balances exist in the payload type at all (1.1 compile-pinned).
- **Containment (BFLA-adjacent):** the sidecar is referenced ONLY by its own namespace, its test, the entry script, and the `ws` package script — ZERO references in `backend/graphql/**` or `app/api/**` (grep evidence); no HTTP page route exists for it (plan §3.4).
- **Log hygiene (REQ-037):** lifecycle logs carry `connId` + `userId` (+ policy reason/code/errorName) only — no tokens, no client IPs, no payload content (grep evidence over every `logger.*` call site); `logger` from `@/backend/lib/logger` exclusively, zero `console.*` (grep).

## 9. Deviations

- **D-1 — No shape-guard re-validation inside the sidecar (plan-text vs 2.5 BINDING):** plan §4.3 says the sidecar validates "every received envelope with a runtime shape guard BEFORE touching any connection" — but 2.5's BINDING (later, more specific, and already test-locked) puts that guard INSIDE the transport adapters (`parseFanoutEnvelope` on the Redis subscribe side), so envelopes arrive at the sidecar ALREADY validated. The sidecar therefore performs NO duplicate validation; instead it re-applies the allowlisted payload projection at EGRESS (`projectFanoutPayload`), which additionally hardens the in-process tap path (objects delivered without serialization). The Tier-2 malformed-drop test runs through the REAL Redis adapter to prove the guard is in the loop end-to-end.
- **D-2 — Subscribe-side factory export added to the 2.5 module:** the plan's topology needs the sidecar to select its subscription source through the same env-driven factory as the publish side; 2.5 shipped only `resolveFanoutTransport` typed to the publish-only port. This task added `resolveFanoutSubscriptionSource(options?)` over the SAME selection core (additive; the publish signature and all 7 pre-existing factory tests are untouched — layer suite 83/0/684 ×2 proves no drift).
- **D-3 — Handshake rejections deliver policy closes via the UPGRADE path, not bare HTTP statuses:** the task text says "close 4401/4429" — a WebSocket close code can only be delivered on an upgraded socket. For 4401/4429 the fetch handler upgrades with a rejection payload that `open()` immediately policy-closes (the client observes the close code); the Origin gate (pre-identity) rejects pre-upgrade with HTTP 403 (the strongest CSWSH posture — never upgrade a foreign origin). Bare HTTP fallbacks (401/429) exist only for the upgrade-failed edge.
- **D-4 — "Repeated abuse MAY policy-close" not exercised:** REQ-034's MAY-clause is optional; the shipped behavior ignores every application frame indefinitely (simplest compliant posture, no abuse-counter state — which also keeps the bounded-state surface minimal). Recorded so reviewers don't flag the absence.
- **D-5 — Bun's native client normalizes close code 1001 → 1000 (and surfaces pre-upgrade rejections as 1002):** the graceful-shutdown and Origin-rejection assertions therefore read the WIRE bytes through a minimal raw-TCP peer (close-frame parse) for 1001, and assert `opened === false` + code for rejections — documented in `backend/ws/AGENTS.md` as the test technique.
- **D-6 — `bun test test/workflows` needs the runner-guard bypass:** the repo's test-runner guard now intercepts bare `bun test` (the mandated gate command predates it); the gate runs as `KOTTABY_TEST_RUNNER_OK=1 bun test test/workflows` with identical counts (33/0/238). Recorded for 2.M and future executors.
- **D-7 — Redis-selected boot fails FAST without a reachable Redis (observable in this sandbox):** `.env` ships `REDIS_URL` (no Redis server here) → the default ladder selects the Redis bus → boot logs structured `NOTIFICATION_FANOUT_REDIS_UNAVAILABLE` + `MaxRetriesPerRequestError` and exits 1. This is the intended REQ-024 misconfiguration posture ("fails fast at resolution instead of degrading silently" — 2.5 outcome), verified in the smoke; dev/demo boots in this sandbox use `NOTIFICATION_FANOUT_TRANSPORT=in-process`.
