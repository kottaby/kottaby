## 6. SEC — Security & Tenancy Audit (1.5.SEC)

- **No secrets logged:** `backend/lib/env.ts` contains **zero logging vocabulary** — no `console.*`, no `logger`, no `logDomainError` (test source-pin; the module structurally cannot emit env values anywhere). The module docblock's guarantee ("it only reads env vars") is preserved.
- **`WS_ALLOWED_ORIGINS` has NO wildcard default — and no wildcard at ANY resolution layer:** the default is the frozen localhost pair `["http://localhost:3000", "http://127.0.0.1:3000"]` (mirroring the existing `app/api/set-locale/route.ts` origin-allowlist precedent), explicit `*` entries are **discarded at resolution**, and an all-wildcard value degrades to the localhost default — **fail-closed** (in production an all-wildcard misconfiguration rejects every real origin rather than accepting everyone). Rationale: the WS handshake is credentialed (cookie), so an allow-all origin would re-open the CSWSH hole the allowlist exists to close (consistent with the wildcard-ACAO prohibition in `docs/graphql/error-handling-contract.md` §6).
- **Transport default is in-process unless Redis config is explicitly present:** implemented as the documented default ladder — explicit valid value wins; unset/empty/unknown → `"redis"` iff `REDIS_URL` (trimmed, non-empty) is set, else `"in-process"`. An unknown value (`kafka`) can never select the Redis transport by itself. The always-available in-process tap is the failure-safe arm (tests/single-process dev), matching plan §4.3 ("RedisPubSubTransport … selected when Redis connection env config exists").
- **No tenancy surface:** config resolution only; no identity, no DB, no I/O, no logging — nothing user-scoped exists in this change.

## 9. Carry-Forward Knowledge

1. **`@typescript-eslint/prefer-nullish-coalescing` (type-aware tier) flags `x || undefined` even when `??` would change semantics** — for empty-string-means-absent resolution, use an if-statement helper (see `trimmedEnvValue`), never `||`.
2. **oxlint `no-unsafe-type-assertion` flags `readonly T[] as T[]`** in tests too — use `Reflect.set`/`Object.isFrozen` for frozen-array mutation proofs instead of a mutable-cast push.
3. **The test preloads cache env at process start:** `bunfig.toml` preloads (`ensure-env.ts`) call `ensureEnvironmentValidated()` → `getEnvironmentConfig()` BEFORE any test file runs, so the snapshot is pre-cached; env-mutating suites must `resetEnvironmentCache()` after every mutation (the fixture pattern in `env.test.ts` handles this in `beforeEach`/`afterEach`). The runner also passes the parent process env through, so `.env` values (e.g. `REDIS_URL`) ARE present in test processes — hermetic default assertions must explicitly delete the keys.
4. **The sidecar test suites (2.8) should use `WS_PORT=0`** — the resolver deliberately accepts 0 as "bind an ephemeral OS port" (documented + boundary-tested), avoiding port races in parallel test runs.
5. **`getWebSocketAllowedOrigins()` returns a FROZEN array** — downstream must not attempt mutation (throws in strict mode); build a new array (`[...origins]`) if a Set/Map view is needed (the set-locale route's `new Set([...])` pattern).
