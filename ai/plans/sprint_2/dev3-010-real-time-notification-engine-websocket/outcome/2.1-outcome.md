### `tracked-fixtures.ts`

```typescript
export interface TrackedFixtureRegisterOptions {
  readonly key?: string;      // registry key; default = physical table name
  readonly idColumn?: PgColumn; // PK override; default = table's `id` column
}
export interface TrackedFixtureRecord {
  readonly key: string;       // registry key (default: getTableName(table))
  readonly table: PgTable;
  readonly idColumn: PgColumn;
  readonly id: number;
}
export interface TrackedFixtureCleanupReport {
  readonly deletedCount: number;         // DELETE statements executed
  readonly verifiedAbsentCount: number;  // rows proven absent post-teardown
  readonly deletedKeys: readonly string[]; // keys in DELETE execution order (reverse registration)
}
export class TrackedFixtures {
  get records(): readonly TrackedFixtureRecord[]; // frozen snapshot, registration order
  get size(): number;
  register(table: PgTable, id: number, options?: TrackedFixtureRegisterOptions): void;
  async exists(record: TrackedFixtureRecord): Promise<boolean>;
  async verifyAllAbsent(): Promise<void>;   // throws naming every `key#id` still present
  async cleanup(): Promise<TrackedFixtureCleanupReport>; // reverse-order delete + verify; throws on residue; empties registry on success
}
```

### `spied-transport.ts`

```typescript
export interface FanoutTransportLike {  // structural mirror of the planned fan-out transport port
  publishFanout(userIds: readonly number[], payload: RealtimeNotificationPayload): Promise<void>;
}
export interface FanoutPublishCall {
  readonly userIds: readonly number[];   // frozen copy of what was handed in
  readonly payload: RealtimeNotificationPayload;
}
export class SpiedFanoutTransport implements FanoutTransportLike {
  async publishFanout(userIds: readonly number[], payload: RealtimeNotificationPayload): Promise<void>;
  get calls(): readonly FanoutPublishCall[];  // frozen snapshot, publish order
  get publishCount(): number;
  get lastCall(): FanoutPublishCall | null;
  get publishedUserIds(): readonly number[];  // flattened, repeats preserved ("zero pushes" = toHaveLength(0))
  clear(): void;
}
```

## 5. SEC — Security & Tenancy Audit (2.1.SEC)

- **Actor-context resolves permissions ONLY through REAL user fixtures.** Every provisioning helper creates a genuine `users` row with the requested `role` (via `createTestUser` from `entity-setup.ts` — never seed data) plus the matching role-child row (`students` / approved `teacher` / `parents` / `admin`). There is no permission stub, no role override hook, no mocked auth context anywhere in the helpers — the self-test pins each actor's `users.role` and role-child row **in the database** (not just on the returned record).
- **Monkey-patching prohibition is DOCUMENTED in `test/workflows/AGENTS.md`:** rule 4 — "Never monkey-patch role/permission resolution in a journey — negative steps must fail through the real authorization/ownership checks" (pre-existing, retained) + factory pointer "REAL `users` rows plus REAL role-child rows … never permission stubs"; the actor-context header docblock repeats the prohibition.
- **Teardown honesty is enforced, not promised:** `cleanup()` re-probes every registered row and THROWS on residue — a journey that leaks fixtures fails its own `afterAll`. `register()` refuses garbage ids (a bogus id would vacuously pass the existence check and silently leak a real row).
- **No external channel is ever touched:** `SpiedFanoutTransport.publishFanout` records and returns — it performs zero I/O (no Redis, no sockets, no filesystem); the class carries no secrets and no account identifiers beyond the ids the engine itself passes.
- **No tenancy surface in the generic helpers:** `TrackedFixtures` knows tables/columns/ids only; `actor-context` inserts exactly the sanctioned fixture shape (entity-setup defaults + role rows).
