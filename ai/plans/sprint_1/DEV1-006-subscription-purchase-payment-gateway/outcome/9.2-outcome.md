## Decision log

1. **File placement + wiring = plan-catalog mirror (task-mandated).** The task pins the exact CREATE paths (root-level `mutation/subscription-purchase.mutation.ts`, `query/subscription.query.ts`) and says to register them "follow how plan-catalog.mutation.ts is registered" — i.e. via the TOP-LEVEL `mutation/index.ts` / `query/index.ts` barrels, exactly as its DEV1-005 sibling is. This deliberately deviates from 9.1's carry-forward note ("add side-effect imports to `mutation/billing/index.ts` + `query/billing/index.ts`"), which assumed billing/ sub-directory placement; both wirings reach `gqlSchema.ts` through the same single top-level import, so nothing functional differs. The billing sub-barrels are untouched.
2. **Input lives in the Pothos layer, on the purchase leaf.** `mutation/AGENTS.md` forbids input definitions in mutation files; plan-catalog co-locates its inputs with the object in the pothos leaf and the mutation imports them. `purchase-checkout.pothos.ts` already holds the purchase payload pair and is barrel-exported, so the whole purchase wire contract (input → payload → checkout) sits on one leaf with zero barrel churn. String-named `inputType` per the AGENTS input pattern (9.1 carry-forward item 2).
3. **Service-parameter adaptation of the plan's delegation shorthand.** Plan §3.2 writes `purchase(ctx.user.id, coercePlanId(args.input.planId, ctx.locale), …)`, but the landed 6.1 service signature is `purchase(studentUserId, input: PurchaseSubscriptionInput, idempotencyKey: string | null, locale, outerTx?)` with the service-level `{ readonly planId: number }` whitelist — so the resolver builds `{ planId: coercePlanId(args.input.planId, ctx.locale) }`. Semantically identical to the plan's intent (coercion at the resolver boundary, identity server-bound); noted here so 9.3 doesn't "fix" it.
4. **`ctx.idempotencyKey ?? null` — type-level only.** `Context.idempotencyKey` is optional in the TYPE (`?: string | null`, so pre-existing fixtures compile) but always materialized by `createGraphQLContext` (`null` when the header is absent). The service takes `string | null`; the coalesce leg changes nothing at runtime and the key stays verbatim (never trimmed/coerced — unlike `createSession`, whose service takes a bare string and therefore coalesced to `""`).
5. **No resolver-level localized errors.** The only throw is the narrowing-guard `UnauthorizedError("Authentication required.")` — the verbatim wallet/session-lifecycle precedent (unreachable in practice behind the `authenticated` scope leg; exists purely for TS narrowing under the no-non-null-assertion rule). All localized messaging is service-side via the propagated `ctx.locale`.

## Carry-forward (for 9.3 / 10.x)

1. **Operation names + payload shapes to test (9.3):** mutation `purchaseSubscription(input: PurchaseSubscriptionInput!)` → `PurchaseSubscriptionPayload { subscription: StudentSubscription!, payment: StudentPayment!, checkout: PaymentCheckout! }`; query `mySubscriptions` → `[StudentSubscription!]!`. Both student-only: expect 401 (`UNAUTHORIZED`) anonymous, 403 (`FORBIDDEN`) for parent/teacher/admin (admin included — DEV1-009 owns admin purchase surfaces), student happy path for the rest. The 401/403 split is enforced by the `$all` conjunction (Pothos `defaultStrategy: "any"` makes a plain map wrong).
2. **Error channels already pinned service-side (6.1):** missing/over-length key → 422 `VALIDATION` (`subscriptionPurchase.idempotencyKeyRequired`); same-caller replay → 409 `DUPLICATE_REQUEST`; foreign-caller key → oracle-safe 404 `PAYMENT_NOT_FOUND` (generic `notFound` message); unknown/inactive plan → `PLAN_NOT_FOUND` (`planNotPurchasable`); NULL lane → 422 `PLAN_LANE_UNCONFIGURED`; reference collision → 409 `CONFLICT`. A replay THROWS — it never returns a row.
3. **Idempotency transport:** the key rides the `X-Idempotency-Key` header captured once in `createGraphQLContext` — 9.3 suites must set the header (not a GraphQL argument); absent header reaches the service as `null` and fails VALIDATION pre-DB.
4. **Wire-name reminder:** the entity is `StudentSubscription` (never `Subscription` — reserved for the root slot, permanently); `mySubscriptions` isolation suites must select on `StudentSubscription` fields (`id`, `planId`, `status`, dates as ISO `String`).
5. **`gql/graphql.ts` will change only when 9.3/10.x add documents** referencing the new surface (operation-referenced emission — verified this task).
6. **`Plan.balanceLane` service-side validation is 10.1's scope** (resolver already passes `args.input.balanceLane` through; unchanged by 9.2).
