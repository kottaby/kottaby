## Cross-File Dependencies Discovered (for 6.1 / 7.1 / 8.1)

1. **6.1 (purchase service):** call `getPaymentGateway(ctx.locale)` OUTSIDE the tx → `createCheckout({studentId, planId, amount: plan.price, currency: plan.currency})`; write `paymentMethod = session.provider` (enum member, never `"mock"` literal) + `paymentReference = session.providerReference`; return `checkout: session` as `PurchaseSubscriptionReturnType.checkout`.
2. **7.1 (activation service):** receive ALREADY-VERIFIED `PaymentWebhookEvent` (outcome is the `"confirmed"|"failed"` literal union, NOT a pgEnum mirror); amount/currency mismatch → quarantine (route owns logging discipline).
3. **8.1 (webhook route):** wire `isPaymentWebhookEnabled()` (bare 404 when false), `getPaymentWebhookSecret()` + `verifyWebhookSignature(rawBody, request.headers.get("x-payment-signature"), secret)` (5.2), then `getPaymentGateway().parseWebhookEvent(rawBody)` inside try/catch — the `PAYMENT_WEBHOOK_MALFORMED` `ValidationError` must become a masked 400-family envelope per plan §3.4 (custom code → BAD_REQUEST fallback in `statusForTransportCode`).
4. **Kill-switch default is fail-closed:** unset `PAYMENT_WEBHOOK_ENABLED` ⇒ disabled; `.env`/`.env.test` currently set `PAYMENT_WEBHOOK_ENABLED=true` for dev — deployment checklist must NOT ship that value to production with the mock provider.
5. **Factory is the only mock seam:** 6.1.TE gateway mocking should go through `getPaymentGateway`/`resetPaymentGateway` (env `PAYMENT_GATEWAY_PROVIDER`) or by injecting a test double where the service accepts one — do NOT construct `MockPaymentGatewayAdapter` in domain code.
6. **Locale-key debt (non-blocking):** factory/adapter errors reuse the generic `validation` leaf; a dedicated `paymentGateway` error group (per REQ-051 pattern) can be added with the 6.1 `subscriptionPurchase` keys without touching this module's code paths (only message construction).
