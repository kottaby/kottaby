## Summary

Owner-scoped subscription listing in `backend/services/billing/subscription-purchase.service.ts`:

```ts
listOwn(studentUserId: number, locale?: string, tx?: DBQueryExecutor): Promise<SubscriptionReturnType[]>
```

- Single owner-scoped read through `SubscriptionRepository.listByUserId(studentUserId, tx)` (`WHERE user_id = ? ORDER BY created_at DESC`) — the owner predicate IS the read scope. NO id-addressed read exists on the service or repository (BOLA dead by construction — REQ-041).
- Pre-DB identifier guard: a non-positive-safe-integer caller id is the canonical localized `VALIDATION` denial, never a SQL round-trip.
- `locale` is a tolerated optional param (symmetry with the mutation surface; resolves the errors bundle for the identifier guard via `getServerTranslations(locale ?? "en")` — property access only).
- Raw rows are mapped onto the strongly-typed `SubscriptionReturnType` (`status` → `SubscriptionStatus`, `paymentMethod` → `PaymentGateway | null`) with cast-free total-over-vocabulary mappers — raw `$inferSelect` rows are not assignable to the ReturnType's enum fields.
- `tx?: DBQueryExecutor` is propagated to the repository read so a caller-owned flow stays atomic (matches plan §4.1 exactly).
