## Summary

Pure, fail-closed webhook signature verifier extracted per the plan's testable-helper requirement: `verifyWebhookSignature(rawBody, signatureHeader, secret): boolean` in `backend/services/billing/payment-gateway/webhook-signature.helpers.ts`. Computes the lowercase-hex HMAC-SHA256 of the EXACT raw body under the shared secret, then compares presented vs expected through the `bearerSecretMatches` idiom copied from `app/api/cron/sweep-sessions/route.ts:66-73` — both sides hashed to fixed-length SHA-256 digests before `timingSafeEqual`, so no length leak, no early exit. Every degenerate input (missing header, empty signature, empty secret, whitespace header) returns `false`; the function NEVER throws. Zero env reads, zero DB, zero logging — pure over its three arguments.

## Security Posture Notes (for 8.1 route wiring)

- The helper is byte-exact on the body: the route MUST pass the body string exactly as read ONCE via `request.text()` (re-serialization invalidates signatures) and BEFORE any JSON parsing.
- Deny decisions never throw and never log — REQ-044 hygiene (no secret, no raw payload in logs) is structurally guaranteed at this layer; route-side logging stays reference/outcome-only.
- Empty-secret deployments fail closed (`false` for every callback) even though `getPaymentWebhookSecret()` returns `undefined` — route should treat `undefined` as "reject all" without calling the helper.
- Comparison is case-sensitive lowercase-hex (idiom parity with `bearerSecretMatches`). If a real Sprint-2 gateway emits uppercase hex, the adapter-layer normalization decision belongs to that ticket — NOT a widening here.
