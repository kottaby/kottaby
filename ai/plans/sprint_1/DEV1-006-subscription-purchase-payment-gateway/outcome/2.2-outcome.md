Probe-methodology notes (cost me two iterations, recorded for whoever wires 4.2):
- PGlite probes MUST re-create/keep the probe row across savepoint rollbacks: `ROLLBACK TO SAVEPOINT` placed **before** the INSERT erased the row, after which every UPDATE matched 0 rows → no trigger fired → false "ALLOWED" (rowCount=0 was the tell). Per-case savepoint must be created **after** the INSERT.
- `now()` is transaction-stable: `SET created_at=now()` inside the same transaction is a no-op change and correctly passes the freeze. Use a literal timestamp (e.g. `'2020-01-01 00:00:00'::timestamp`) to test the created_at freeze.
- Only 1 student is seeded (id=4): student_id tamper used a non-existent id (999999) — the BEFORE trigger raises before FK enforcement, so the freeze (not the FK) is what blocks.

## Carry-Forward Knowledge

1. **Pairing convention (from `backend/db/scripts/applyCustomMigrations.ts`):** every new `backend/db/migration/*.sql` is auto-bundled into its own timestamped `backend/drizzle/<ts>_custom_<fileslug>/` folder on the next `migrate` (manifest = filename+sha256 in sidecar `.custom-migrations.json`; delta = new/changed files; one folder per file, applied alphabetically). SQLite parity files (`*-sqlite.sql`) are NEVER bundled — they must be added to the `EXCLUDED_FILES` hardcoded set in `applyCustomMigrations.ts` (this task added the 4- sqlite filename; future sqlite parity files need the same one-line entry).
2. **Exact function name (stable contract for repos/tests):** `prevent_student_payments_update()` (plpgsql, `RETURNS trigger`, SQLSTATE P0001 via bare `RAISE EXCEPTION`); executing trigger `prevent_student_payments_update_trigger` (BEFORE UPDATE … FOR EACH ROW) on `student_payments`. Do NOT recreate triggers in later migrations — replacing the function re-arms the guard. DELETE guard: `prevent_student_payments_delete()` / `prevent_student_payments_delete_trigger` (unchanged).
3. **Error message (verbatim, for 4.2/6.1/7.1 envelope tests):** `student_payments is immutable — UPDATE is permitted only to transition a pending payment to paid or failed with all financial columns unchanged`.
4. **Frozen columns are null-safe:** `IS NOT DISTINCT FROM` (PG) / `IS` (SQLite) — a `SET subscription_id = NULL` swap on a row that already has NULL is a no-op and correctly allowed; a NULL→value or value→NULL swap is blocked.
5. **Fresh-DB convergence:** 3- file (strict guard) applies before 4- file (amendment) alphabetically; on existing DBs the delta folder replaces the function in place. Both paths end with the amended guard.
