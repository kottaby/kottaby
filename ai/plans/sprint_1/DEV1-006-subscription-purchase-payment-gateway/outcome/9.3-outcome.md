## Harness decision (documented deviation from plan §9 wording)

Plan §9 lists `testClient` + `setupTestServerLifecycle` for this layer. The two
prior-incarnation suites already probe-proved and documented why the live harness
cannot run in this worktree (Turbopack rejects the out-of-root `node_modules`
symlink; the single-process PGlite provider gives the spawned server a disjoint
database snapshot, so wire boundary and test process can never observe the same
rows). The three suites therefore execute in-process against the canonical
`graphQLSchema` — the exact `plan-catalog.schema.test.ts` / `plan-catalog.roles.test.ts`
pattern (same schema object, scope gate, resolver stack, services, and live test
database the HTTP boundary uses). The `X-Idempotency-Key` header→context transport
mapping is pinned exhaustively by `backend/graphql/test/context-keys.test.ts`
(verbatim, case-insensitive, absent → exactly `null`); the replay suite pins the
replay SEMANTICS behind that transport, reaching them through the same resolver
stack. Committed fixtures in `beforeAll` inside ONE committing `db.transaction`;
hard-delete cleanup in `afterAll`; zero-residue proof in every suite (the
journey-layer committed-fixture convention — `runInRollback` is impossible here:
services spawn their own top-level transactions).

## ENVIRONMENTAL INCIDENT + REPAIR (carry-forward critical)

The interrupted live-harness replay run left the shared PGlite data dir
(`PGLITE_DATA_DIR=/home/z/my-project/db/pglite`) corrupted: the spawned dev server
and the test process had both opened the same data dir; the killed server left a
WAL whose checkpoint record could not be located
(`PANIC: could not locate a valid checkpoint record at 0/1B22C30` → `RuntimeError:
Aborted()` on EVERY subsequent PGlite open, all suites red). No postgres binaries
exist in the sandbox, so no `pg_resetwal` repair was possible. Repair performed
(filesystem-level, no repo files touched):

1. `mv /home/z/my-project/db/pglite /home/z/my-project/db/pglite-corrupt-20260908`
   (archived, 41 MB, deletable at will — dev/test data only).
2. Fresh empty dir; `bun run db migrate` → all 6 committed drizzle folders applied
   (extensions, functions, initial schema, immutability-triggers,
   student-payments-status-transition, ancient_scarecrow) + enum pre-commit. `db
   reset`/`cleanGenerate` (repo-disabled) were NOT used.
3. `bun run db seed` → plans catalog + demo data re-seeded.
4. Probe `SELECT count(*) FROM users` → healthy. All suites green again.

**Rule for 11.1 and every future DB task in this worktree: NEVER let the
live-server harness spawn while DB-backed suites run here — one PGlite open per
data dir, and always verify a suite can open the DB before debugging test
failures.** All three suites' committed-row oracles + the disjoint-snapshot reality
are why the in-process harness is the only viable one here.

## Carry-forward (for 11.1)

1. **In-process harness is the proven pattern here** — copy the sibling header
   explanation + `contextFor`/`expectDomainDenial` helpers; do NOT reach for
   `setupTestServerLifecycle` in this worktree (see incident above).
2. **Cleanup order proven (and why):** `student_payments` first under
   `withImmutabilityTriggersSuspended(["student_payments"])` (append-only trigger
   blocks DELETE), then `student_subscriptions` (cascade FKs) →
   `subscription_purchase_idempotency` claims (before subscriptions, so no set-null
   write fires) → `subscriptions` → `plans` → role-child rows (`students`/
   `parents`/`teacher`/`admin`) → `users` (claims also cascade with users; explicit
   delete keeps the order explicit). Residue proof after every delete leg.
3. **Purchase pending-set oracle:** `{subs:1, payments:1, junction:1, claims:1}`
   per purchasing student; claim `subscriptionId` backfilled with the winning id;
   key verbatim (never trimmed).
4. **Error channels pinned at the GraphQL boundary:** 401 `UNAUTHORIZED` (anonymous
   both ops), 403 `FORBIDDEN` (all non-students incl. admin/supervisor shape, both
   ops), 422 `VALIDATION` (absent key), 404 `PLAN_NOT_FOUND` (inactive/unknown/
   malformed id), 409 `DUPLICATE_REQUEST` (same-caller replay — throws, never
   returns), 404 `PAYMENT_NOT_FOUND` with generic `notFound` copy (foreign replay —
   no existence leak).
5. **Wire names to reuse:** `StudentSubscription` (never `Subscription`),
   `StudentPayment`, `PurchaseSubscriptionPayload{subscription,payment,checkout}`,
   `PaymentCheckout{provider,providerReference,checkoutUrl?}`, enums serialized as
   TS keys verbatim (`Pending`, `Mock`).
6. **Journey tests (11.1) can rely on the suites' fixtures being ephemeral:** every
   graphql suite leaves zero rows (proven twice); the shared DB now contains ONLY
   seed data + the suites' own per-run fixtures.
