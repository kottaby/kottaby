## Summary

The balance-lane contract is now enforced end-to-end through the plan catalog. The service rejects any `balanceLane` that is not a valid `SubscriptionCreditLane` member or an explicit `null` — BEFORE any DB write — on BOTH create and update paths, so no unroutable lane can ever be persisted (activation crediting resolves a balance column from this value; an unknown lane would credit nothing). The GraphQL `updatePlan` resolver, which was silently DROPPING the lane field from the admin patch (input-mapping gap: the SDL exposed `UpdatePlanInput.balanceLane` since 9.1 but the resolver never forwarded it), now passes it through with null-aware semantics. Pre-landed type + repo work (from the 2.3 seed unblock) was verified line-by-line and required no changes. The pure field validators were extracted into a sibling `plan-catalog.helpers.ts` after adding the lane validator pushed the service file past the repo's 300-code-line oxlint budget (the file was at 299/300 before this task).

## Validation decision (the error-key ruling)

No existing locale key fits "unknown lane member": the `planCatalog` group has only per-field scalar messages (title/sessionCount/price/currency/intervalDays), and `subscriptionPurchase.planLaneUnconfigured` is the PURCHASE-time fail-closed copy ("this plan cannot be purchased yet…") — semantically wrong for an admin-input rejection. Per the task directive (no new locale keys unless strictly necessary), the rejection uses the **generic validation label** `errorsTranslations.validation` ("Invalid input." / "إدخال غير صحيح.") as the field-error message, with machine code `PLAN_BALANCE_LANE_INVALID` and form path `field: "balanceLane"` (sibling `PLAN_*` field-code convention, RHF-consumable). The aggregate throw is `ValidationError(tErrors.validation, fields)` — identical shape to every other catalog field rejection. REQ-051's `subscriptionPurchase` group is untouched.

Semantics pinned by tests: `undefined` (field absent) → skip + leave stored lane untouched; `null` → clear to NULL (fail-closed purchase state); valid member → persist; anything else → `ValidationError` before the DB write (defense-in-depth behind the GraphQL enum coercion, which already blocks unknown wire values pre-resolver — the service guard covers non-GraphQL callers: seeds, services, scripts).
