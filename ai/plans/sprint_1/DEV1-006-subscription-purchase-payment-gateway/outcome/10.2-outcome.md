**Date:** 2026-09-08
**Agent:** Admin Form Lane Subagent
**Requirements:** REQ-003, REQ-004, REQ-062, REQ-064, REQ-065, REQ-075

## Summary

The admin plan create/edit dialog now owns a required balance-lane select over the three `SubscriptionCreditLane` members (Hifz / Tajweed / Reviews) with localized labels from the `plans` namespace. Create payloads always carry `balanceLane` (the client validation blocks laneless submits); update payloads ride the backend's null-aware contract — an untouched lane is sent as explicit `undefined` (JSON serialization drops it → stored lane untouched server-side), a changed lane is sent as the enum member, and no `null` is ever sent because the form has no clear affordance (the lane is mandatory once picked; only legacy laneless rows start empty and force a pick). Arabic/RTL renders the Arabic lane labels and composes the identical enum payload. Codegen types were consumed directly (9.1); no schema/graph document changes beyond the `balanceLane` selection-set lines the query needs to hydrate the pre-filled select.

## Cross-File Dependencies Discovered

- `PlanFormFields.tsx` ↔ `usePlanForm.ts`: the select reads/writes `form.balanceLane` (raw string) and the hook's lookup is the single string→enum boundary; changing one without the other silently breaks the payload.
- `usePlanFormDialog.ts` ↔ `selectedPlanForEdit.balanceLane`: the untouched-lane suppression compares against the query-returned member, which requires `balanceLane` to stay in the `adminPlans` selection set — removing it from the document re-introduces a wire-delta on every untouched edit save.
- `shared/locale/plans` ↔ `PlanCatalogContainer.test.tsx`: the suite warms `Plans.getLabels` for both locales in-file (translation-preload warming loop deliberately untouched — admin suites own their in-file warming per BroadcastCompose precedent); key renames fail fast at module load.
- 10.1's field-error contract (`PLAN_BALANCE_LANE_INVALID` on `balanceLane`) is consumable via the existing `serverFieldErrors` plumbing — untested here because the mutation-mock envelope path belongs to the broadcast suite's seam; noted for review waves.
