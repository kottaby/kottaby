## 4. 2.3.SEC — Security & Tenancy Audit

- **Student scoping via `session.student_id` only:** `findLatestUngradedByStudentId` accepts a `studentId`, never a homework id — the caller cannot aim the read at a specific row; the target row is decided by the DB (newest ungraded of THAT student's sessions). The student id rides a bound parameter (`$1`) in both branches; the Drizzle branch composes `eq(session.studentId, studentId)` (parameterized).
- **Guarded UPDATE cannot touch any other row:** the WHERE clause is `id = $id AND current_grade IS NULL AND revision_grade IS NULL` — id equality (typed `number`, bound) + NULL-guards; there is no column-permissive path, no `OR` leg, no dynamic predicate composition; a tampered id matches at most the one row and only while BOTH grades are NULL. Under parameter tampering the worst case is "some row the caller already knew" — never a full-table or multi-row write (no `inArray`, no `sql.raw`, no unbounded WHERE).
- **No LIKE/ILIKE/pattern surface** (grep-verified); no cross-tenant predicate needed — student scoping is the predicate (the caller-supplied studentId is the service-resolved `probe.studentId`, never raw client input — 2.7 passes the gate-locked probe's value).
- **No BOPLA shape:** insert param typed `HomeWorkInsertType`; 2.7 maps blocks field-by-field (`jadid → current_*`, `madi → revision_*`) from guard-validated state.
- **Raw 23505/22P02 surface:** driver errors propagate untranslated (transport masks internals); repo injects no caller data into error text.
