## 3. Mapper design (`toSurahJuzRef` in `home-work.pothos.ts`)

- ONE module-private mapper shared by both `currentSurahJuz` and `revisionSurahJuz`, mapping the `surah_juz_ref` pgEnum string union carried by `NonNullable<HomeWorkReturnType["currentSurahJuz"]>` → the `SurahJuzRef` TS enum. Parameter type is an inline projection of the canonical row type — no local type declared.
- Compile-time exhaustiveness: 5 surah legs as equality-guard early returns + an exhaustive 30-case `juz_*` switch, NO `default`, ending in `const exhaustive: never = value; throw new Error(...)`. A future pgEnum member (surah OR juz) without a branch reaches the tail non-`never` → tsgo error. Runtime fail-closed: an unknown DB string surfaces as a resolver error, never passes through.
- **Deviation DV-A (shape, not semantics):** the 5 surah legs are single-line early returns instead of switch cases — the full 35 × 2-line single-switch body is 76 code lines and fails oxlint `max-lines-per-function` (max 75). Sequential equality guards narrow the scrutinee identically (tsgo green proves the `never` tail is genuinely consumed). Every load-bearing property of the `toSessionStatus` pattern is preserved: no `default`, no cast, compile-time exhaustiveness, fail-closed runtime throw.

## 7. Deviations (none silent)

- **DV-A — mapper shape:** surah legs as equality-guard early returns (lint ceiling), semantics identical to the bound `toSessionStatus` pattern (§3 above).

SDL names are EXACTLY the plan names via the string-named `inputType(...)`.
