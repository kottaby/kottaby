## Dispositions

### Fixed in this task

1. **Ayah upper bound missing in `assertHomeWorkBlock` (pentester LOW)** — the guard accepted any positive safe integer ayah, so values above the PostgreSQL integer range died later as an unmapped storage error (500) instead of the typed `VALIDATION` denial. Search confirmed NO shipped mushaf/ayah-count constant exists in the repo (no `MAX_AYAH`/ayah-count/mushaf constant under `shared/constants` or `backend/constants`; the enum ships surah/juz vocabulary only), so the bound is the storage ceiling.
   - Fix: `backend/services/classes/session-report.guards.ts` — new module constant `MAX_AYAH_VALUE = 2_147_483_647` (:60, PG 4-byte integer ceiling of the `home_work` ayah columns) and both endpoints now checked against it (:150-151), routing overflow into `homeworkAyahRangeInvalid` before any DB work.
   - Tests: `backend/services/classes/session-report.guards.test.ts` — new Tier-2 boundary case (span at the bound accepted; bound+1 on either endpoint rejected with the ayah-range key); `AYAH_POOL` fuzz values adjusted to the new boundary pair (2_147_483_647 / 2_147_483_648). Journey step-4 sweep payloads re-checked — all small values, valid as written.

2. **Report wave-context INNER JOIN on `students` (backend LOW)** — `findReportWaveContextById` INNER-joined the `students` bridge, so a session whose student user lacks a `students` row (out-of-band data edge; the RESTRICT FK makes the shape unreachable through ordinary inserts) nulled the whole wave context and threw mid-transaction in `notifySessionReportReady`, rolling back the submission.
   - Fix: `backend/db/repo/classes/session.repository.helpers.ts` — the `students` leg changed to LEFT JOIN in both executors (:337 Drizzle chain, matching the file's existing `leftJoin` pattern; :349 raw-SQL branch). The parent leg stays LEFT JOIN (already nullable/fail-closed); the student/teacher legs stay INNER JOIN off the `users` shared PK (NOT NULL). Both doc comments (`helpers.ts`, the `session.repository.ts` delegate) updated to state the new bridge semantics.
   - Tests: `backend/db/test/repo/classes/session.repository.test.ts` — new rollback-isolated case: a session whose student user has no `students` row still returns the full wave context with `parent: null` and student/teacher present. Fixture rides a tx-scoped `session_replication_role = replica` insert (the RESTRICT FK forbids the shape otherwise); no existing test asserted the INNER behavior (pre-existing wave-context cases: linked parent, unlinked-student-null-parent, unknown id — all unaffected).

3. **Duplicated `isSuppliedBlock` predicate (backend LOW)** — the fail-closed transport-null "supplied block" predicate existed twice with identical semantics (service `~:131`, guards `~:146`).
   - Fix: exported ONCE from the payload-vocabulary home (`session-report.guards.ts:172`); the service imports it (`session-report.service.ts`) and its local copy + doc block were deleted. The now-unused `HomeWorkBlockInput` type import in the service was removed with it. Semantics byte-identical (`typeof value === "object" && value !== null`).

4. **Stale doc line in the service header (backend LOW)** — the pipeline text named `assertActorGovernanceClean` while the code calls `assertTeacherGovernanceClean`.
   - Fix: `backend/services/classes/session-report.service.ts:16` — one line, now names the actual function in clean domain language.
