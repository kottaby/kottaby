**Transport deviation (DV-T3, the one material deviation — recorded, not silent):** under `DB_PROVIDER=pglite` (this sandbox's ONLY test transport, `.env.test`) PGlite is a SINGLE-connection WASM Postgres: concurrent top-level `db.transaction` calls interleave BEGIN/INSERT/COMMIT on one session and poison it (`25P02 current transaction is aborted`) — observed live as raw `DrizzleQueryError`s + a mid-storm read throw in the first run. The storm attempts (and the 2.8 mid-storm reads) are therefore chained through ONE FIFO async queue **only when `IS_PGLITE`** (`serializeOnPglite` helper, header-documented TRANSPORT NOTE); against a real multi-connection pool the queue is bypassed and the storm fires truly concurrently (separate connections, row-lock wait, WAL snapshot reads). This mirrors the established repo precedent (`user-management.chaos.test.ts` / `user-governance.chaos.test.ts` skip concurrency chaos under PGlite entirely) while keeping the storm ACTIVE with the full assertion set: each attempt still opens its own top-level transaction, the losers still lose to the **committed** `reports_session_id_unique` arbiter (the 23505 → typed-conflict mapping is exercised for real, not mocked), and the read observations still interleave between attempts (documented observed behavior: leading `null`s pre-commit → trailing full-row observations post-commit; never throws; never a partial shape). ## 6. 2.7.SEC — Security & Tenancy Audit

- **BOLA — oracle collapse:** an unknown session id and another teacher's session produce the IDENTICAL typed denial — asserted two ways: per-path pins (`SESSION_NOT_FOUND` + `ERRORS_EN.sessionNotFound` in both isolation tests) and the Tier-4 field-by-field identity (constructor, `name`, `code`, message, serialized `extensions`) in `en` AND `ar`. No caller input can discriminate existence vs. ownership; the bounded log differs only in `entityId` (never surfaced to the wire).
- **BOLA — owner gate:** the gate classification keys on `probe.teacherId !== teacherUserId` inside the locked read; the foreign-owner case leaves zero rows and publishes nothing (transport spy at 0).
- **BOLA — governance re-assertion:** a blocked teacher is denied `FORBIDDEN` BEFORE any DB work even when the gate would deny differently (Tier 4 ordering case: zero rows, exactly one governance log, gate log never fired) — the DB row is the authority, defense in depth against still-valid tokens.
- **BOPLA — field-by-field:** the report INSERT whitelists `{sessionId (server arg), teacherNotes (guard-trimmed), studentRatingByTeacher}`; the assignment mapping copies ONLY the six block fields onto the two tracks; grades are structurally absent from the insert (INV-HW3). The Tier-4 smuggle case proves runtime-injected `id/sessionId/teacherId/studentId/createdAt/updatedAt` (input level) and `id/sessionId/currentGrade/revisionGrade/createdAt/updatedAt` (assignment level) never reach storage — `sessionId`/`studentId`/`teacherId` are structurally unreachable from input.
- **BFLA — service re-asserts:** the service re-checks governance itself (it does not trust the resolver scope) AND re-checks ownership inside the transaction; the tier-1 foreign-owner denial is the BFLA proof at the service seam (a valid, clean teacher identity is still denied for a session it does not own).
- **Log hygiene:** exactly ONE `logDomainError` per denial path with `{code, entity, entityId}` only — never payloads, notes, grades, or the other participant's data (asserted via exact `records` equality); success paths assert `logs.records === []`.
- **Wallet/fee purity (REQ-044):** report submission never moves escrow lanes (`students.balance_trial/hifz`), never creates `wallet`/`teacher_transaction` rows, never flips `session.fee_held` — asserted in Tier 1 (per-call) and around every Tier-3 probe (committed scope).
