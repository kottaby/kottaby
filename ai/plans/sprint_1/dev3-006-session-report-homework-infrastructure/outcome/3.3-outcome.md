## 3. Conventions matched

- **`authScopes: { authenticated: true }`** — plain single-key map, NO `$all` (no conjunction to force), mirroring `sessionById`/`cancelSession`: the participant predicate lives entirely service-side; anonymous callers get the `authenticated` scope's 401 pre-resolver.
- **Id shape guard pre-service** — the house helper `requirePositiveIntId(Number(args.sessionId), "sessionId")` (composed with the boundary `Number()` parse because Pothos `ID` args are typed `string | number`); the service re-asserts the positive-safe-integer shape pre-DB with the localized `VALIDATION`.
- **Direct nullable return** — the readers' rows are returned exactly as handed over (no wrapping, no defaults, no re-shaping); unknown id / non-participant / no-row-yet all collapse into the service's identical `null` (oracle-safe).
- **Thin delegation** — identity `ctx.user.id` ONLY; `ctx.locale` propagated for the service's localized id-shape guard; zero repository calls; zero branching logic in the registrations; no try/catch (the readers never raise on gate misses).
- **ctx.user narrowing guard** — same TypeScript-narrowing-only `UnauthorizedError("Authentication required.")` pattern, documented once inside the shared body.
- **Barrel** — side-effect import; file has no named exports.

## 4. Design note (intra-file duplication → shared delegation body)

The two registrations share ONE module-scope delegation body, `resolveParticipantSessionRow(args, ctx, reader)` (parameterized by the `SessionReportService` read function) — the duplication-elimination pattern of `backend/graphql/AGENTS.md`, adapted because the two fields have DIFFERENT output refs:

- A full-field factory à la `registerParticipantSessionsField` (session-lifecycle.query.ts) requires one output type per factory; parameterizing over a generic `ObjectRef` fails here — Pothos's exported `ObjectRef` needs 2–3 type arguments including the builder's `SchemaTypes`, which this builder declares inline (anonymous) at `pothos/builder.ts:73` and doesn't export. Attempted, reverted (`TS2707`).
- First-cut twin standalone registrations tripped the sub-loop's jscpd intra-file duplicate check (1 clone, 29 lines / 276 tokens ≥ min-tokens 75) — exit 1. The shared-body refactor removed the duplicated guard/parse/hand-off block; sub-loop now exit 0.
- The delegation body's `ctx` parameter is the real `Context` type (`@/backend/graphql/gqlContextFactory`, the same handle builder.ts binds); its `args` parameter is an inline projection (`{ readonly sessionId: string | number }`) — no local type declared.
