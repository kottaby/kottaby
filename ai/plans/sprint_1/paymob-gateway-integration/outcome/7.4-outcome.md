## 7.4.SEC — tenancy audit

- **BOLA/BOPLA/BFLA posture:** the view sends ZERO arguments on the wire — the `mySubscriptions` read scope IS the verified caller identity server-side (`backend/graphql/query/subscription.query.ts` re-verified: `authScopes $all { authenticated, role: [Student] }`, resolver resolves `SubscriptionPurchaseService.listOwn(ctx.user.id, ctx.locale)`, owner predicate lives on `user_id` equality). There is no id-addressed or studentId-carrying affordance anywhere in the UI, so no cross-user probe surface exists by construction.
- The page guard (`withPageAuth({ roles: [UserRole.Student] })`) is the ONLY authorization boundary; the container performs no role logic and no identity reads (BOPLA hygiene — identity never derives from input or the wire).
- Rows expose no owner columns on the wire (`StudentSubscription` has no `userId`), so even a hypothetical data leak carries no cross-tenant identifier.
- No secrets, no money mutation, no state write on this surface (read-only view).
