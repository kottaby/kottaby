# Task 5.2 — Cron route — Outcome

## Summary

Landed the reconciliation backstop's HTTP surface: `GET /api/cron/reconcile-paymob-payments` in `app/api/cron/reconcile-paymob-payments/route.ts`, a thin shell over the 5.1 sweep following the sessions sweeper route as the exact template. The gate chain runs existence-before-authentication: (1) the cron mode gates fail closed — anything other than `CRON_EXECUTION_MODE=external` AND `CRON_EXTERNAL_ENABLED=true` answers the BARE endpoint-shaped 404 (no envelope, no code, no requestId — a disabled cron deployment exposes no cron endpoint at all, valid credentials included); (2) the provider configuration gate fails closed — while paymob is not the ACTIVE provider OR the server-to-server API key is unconfigured (unset or whitespace-only, which the typed env parser collapses to `null`), the SAME bare 404 answers even a correctly bearer-authenticated call, because the reconciliation surface does not exist for that deployment and no envelope may prove otherwise — the plan-mandated belt-and-suspenders duplication of the 5.1 service-level gate (the route hides the endpoint; the service stays honest when invoked from anywhere else); (3) the bearer gate — `CRON_SECRET` compared ONLY through the SHA-256-digest-then-`timingSafeEqual` idiom (never a plain string compare; the presented bearer is never accepted via query string), with a missing/empty-configured secret, a missing/blank-presented token, or a mismatch all collapsing into one masked 401 `UNAUTHORIZED` envelope. The authenticated path delegates exactly once with the current instant — `reconcilePendingPaymobPayments({ now: new Date() })` — and serializes the honest per-run tally `{ checked, confirmed, failed, skipped }` into `apiSuccessResponse` (no row identities cross the wire; the zero-count idempotent re-sweep serializes all four counters byte-equally). The catch arm is reserved for true infrastructure breaches (the sweep never throws for provider or outcome content): masked through `apiErrorResponse`'s 500 `INTERNAL_SERVER_ERROR` with one correlated log line from the shared machinery — the handler never lets an error escape raw. Registered in `ROUTE_INVENTORY` as classification `envelope` in the same change set (A4 static assertion stays green), with the frozen-ordering snapshot test and the ground-truth row test updated in lockstep.

Both the cron mode keys and the provider/API-key values are re-read per request through their registered getters (the `CRON_*` trio rides the live `getEnv` path; the provider pair rides the typed cached snapshot the route re-resolves inside GET — the webhook route's landed per-request-read pattern), so a mid-flight flip is honored on the very next run, test-pinned by a three-leg flip sequence.

## Semantic review checklist (5.2.SR)

- **No module-level mutable state:** the route module holds two `const` primitives and functions only; every per-request value (requestId, env reads, the presented bearer, the delegation result) is a local. The route memoizes nothing — no singleton, no cache, no captured config.
- **No dead branches:** every branch is exercised by the suite — the mode gate's two legs plus the both-unset arm (×3 tests), the provider gate's provider/key-unset/whitespace-key arms plus the flip re-read (×4 tests), the bearer gate's `secret === undefined` / `secret.length === 0` / mismatch arms and `bearerSecretMatches`' null-presented and empty-presented early return (×5 tests), the happy path's serialization (×2 tests), and the catch arm (×1 test).
- **No cross-layer imports:** the route imports `node:crypto`, `next/server` (type-only), `@/backend/enum`, `@/backend/lib/{api,env,errors}`, and the billing service module (App Router routes call backend services directly — the layer contract; no repo, no DB, no GraphQL, no frontend imports).
- **Enum value imports:** `PaymentGateway` is a VALUE import in both the route and the test (the provider constant and the env fixtures use the runtime enum members; the widened `PAYMOB_PROVIDER_VALUE: string` keeps the env comparison string-to-string — `no-unsafe-enum-comparison` clean). `NextRequest` is type-only in the route (never constructed there) and a value import in the test (constructed — the set-locale suite's documented detonation guard).
- **Scope = the 2 new files + the inventory row + its pinned suite:** the inventory updates are the SAME change set the route-registration rule mandates (app/AGENTS.md) and the stale-pin rule requires (route-inventory.test.ts's frozen snapshot must move with the registry). No other file touched (`git status` verified before the stage-1 commit).
- **CRON_SECRET compared timing-safe (never `string ===`):** the presented secret reaches exactly one comparator — `bearerSecretMatches` — which digests both sides to fixed-length SHA-256 before `timingSafeEqual`. The only `===`/`!==` string comparisons in the module are the two non-secret cron mode literals and the provider/API-key gate (config-side values, never the bearer). Test-pinned: wrong/missing/blank bearers all deny 401; a valid bearer passes only against the digest compare.
- **Race conditions / env getters:** the `CRON_*` keys are read live per request (`getEnv` → `process.env`, no cache); the provider/API-key pair is read per request through the typed getters inside GET (no module-level capture — the webhook route's landed pattern), so a flip is observable on the next run the moment the env snapshot drops (the suite demonstrates it with `resetEnvironmentCache()`, the same seam the 4.1 suite uses via `resetPaymentGateway()`). Concurrent authenticated runs converge through the 5.1 sweep's own serialization + the activation surface's guarded transitions — the route adds no shared state for them to race on.
- **BOLA/BOPLA/BFLA posture (5.2.SEC):** the route exposes no object references at all — no ids, no query params, no body; the only inputs are the two cron mode flags, the provider/API-key config state, and the bearer secret. The fail-closed gates answer the bare 404 BEFORE the bearer compare, so an unauthenticated/unconfigured prober learns nothing (not even that an auth surface exists — the same no-oracle discipline the webhook kill switch and the sessions sweeper enforce). The success envelope carries only aggregate counts — no row identities cross the wire. Function-level abuse is bounded by the delegate's own batch ceiling (50 rows/run); no attacker-controlled parameter can widen it (the route passes no `batchLimit`).
