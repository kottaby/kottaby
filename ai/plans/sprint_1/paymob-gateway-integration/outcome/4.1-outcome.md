## Security audit (4.1.SEC)

- **Forged HMAC → 401** (attacker-secret signature; message never verified) — test-pinned, service never invoked.
- **Tampered payload → 401** (valid hmac computed over DIFFERENT bytes delivered with a mutated body) — test-pinned.
- **Missing `hmac` → 400** (adapter malformed-family rejection; §3.4's 400 cell) — test-pinned, as is the empty-`hmac` variant.
- **Logs redacted:** the single `logDomainError` line on signature failure carries only the fixed diagnostic + `code` + `requestId` — test-pinned that neither the payload nor the reference appears in the log bag or on the wire; the unreadable-body path deliberately discards the raw transport error message (untrusted peer material) before logging. No `console.*` anywhere (static pin).
- **Constant-time compare not bypassed:** the route contains NO HMAC machinery (static pin forbids `verifyPaymobHmac`/`createHmac`/`paymob.hmac`/`paymob.mapper` in the route source) — verification stays inside the adapter's parser, which delegates to `verifyPaymobHmac`'s digest-based `timingSafeEqual` (3.1.SEC). The route's own mock-branch gate keeps the digest-idiom `verifyWebhookSignature`. The inactive-branch 404 fires before the body is read, so no verification work is even attempted for a gated delivery.
- **No-ops never skip verification:** forged TOKEN and forged refund-shaped deliveries are still denied 401 — ignoring a variant happens only AFTER its signature verifies.
