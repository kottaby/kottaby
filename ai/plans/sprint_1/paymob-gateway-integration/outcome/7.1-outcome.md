## One deliberate deviation: the mutation OPERATION name

The GraphQL operation is named **`PurchaseSubscriptionPlan`**, not `PurchaseSubscription`: the repo's `@graphql-eslint/naming-convention` rule (active in `eslint.config.mjs:456-466`, enforced by sub-loop's type-aware lint lane) forbids the `Subscription` SUFFIX on operation names (reserved for GraphQL subscription semantics). The task-mandated EXPORT names are unchanged (`purchaseSubscriptionMutationDocument`), and the generated TYPE names follow the operation name: `PurchaseSubscriptionPlanMutation(Variables)`. The choice is pinned by the test suite (operation-name contract row) and documented in the file docblock. Root field, wire shape, and selection sets are untouched by this naming.

## Carry-forward for 7.2 / 7.3 / 7.4 (EXACT names the consumers use)

**Documents (import from the barrel `@/frontend/graphql/sharedDocuments` or deep-import `…/billing/subscription-purchase.documents`):**

- `purchaseSubscriptionMutationDocument: TypedDocumentNode<PurchaseSubscriptionPlanMutation, PurchaseSubscriptionPlanMutationVariables>`
- `mySubscriptionsQueryDocument: TypedDocumentNode<MySubscriptionsQuery>` (no-arg — omit variables param)

**Hooks:** this repo's codegen does NOT emit react hooks (plugins are `typescript-operations` + `typed-document-node` only) — consumers call `useQuery` / `useMutation` from `@apollo/client/react` with the document consts (typing flows through the `TypedDocumentNode` generics). `useLazyQuery` is banned.

**Generated types (all in `@/frontend/graphql/generated/gql/graphql`):**

- `PurchaseSubscriptionPlanMutationVariables` = `Exact<{ input: { planId: string | number } }>` — the plan selector is the ONLY client-owned field; the idempotency key is NOT a document variable (travels as the `x-idempotency-key` context header; `DUPLICATE_REQUEST` maps through `error-link.map.ts` as success-equivalent UX).
- `PurchaseSubscriptionPlanMutation` / extracted: `PurchaseSubscriptionPlanMutation_purchaseSubscription{,_subscription,_payment,_checkout}`.
- `MySubscriptionsQuery` / `MySubscriptionsQuery_mySubscriptions` (`MySubscriptionsQueryVariables` = `Exact<{[key: string]: never}>`).
- Enums (wire-name values): `SubscriptionStatus{Active,Cancelled,Expired,Pending,Suspended}` · `PaymentStatus{Failed,Paid,Pending,Refunded}` · `PaymentGateway{BankTransfer,Fawry,Mock,OfflineCash,Other,Paymob,Paypal,Scholarship,Stripe}`.

**Funnel-relevant type facts:**

- `checkout.checkoutUrl: string | null` — the redirect trigger; `null` (mock/server-side providers) is the refetch-instead-of-redirect branch.
- Money is decimal STRINGS (`payment.amount`/`payment.currency`) — render as localized EGP, never client float math.
- `SubscriptionStatus` has **no `Failed` member** — the failed-payment arm for the result page / status chips derives from payment-level truth (`PaymentStatus.Failed` — visible via the mutation payload's `payment` row) plus the display-only GET-redirect hints; a failed purchase leaves the subscription row `Pending`.
- The `StudentSubscription` selection is byte-identical across the mutation and the query — safe to converge cache entries between them.
