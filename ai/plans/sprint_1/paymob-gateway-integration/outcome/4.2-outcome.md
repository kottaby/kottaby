## Security audit (4.2.SEC)

- **Cross-student reference cannot reach another student's subscription (BOLA probe):** Tier-4 test provisions TWO student pairs and settles one reference — the sibling student's subscription, payment row, balance lanes, and notification inbox stay byte-identical/untouched; a mismatched-amount probe through the sibling's reference quarantines with zero mutation. The reference → pair correlation is a single repo lookup scoped by the reference's own unique pair; no id/student id crosses the wire into the decision.
- **Forged failure notification impossible via amount tamper:** a `failed` event with a mismatched amount quarantines BEFORE the decision write — no `markFailedOnce`, no failure notification (test-pinned: quarantine emits nothing).
- **Idempotency-key integrity:** the key is composed ONLY from the VERIFIED event's `providerTransactionId` (post-HMAC-gate — the service trusts the transport's verification contract); the claim digest is `buildEmitClaimKey([recipientId], type, key)` so a key can never address another recipient's inbox.
- **No secrets/PII in logs:** the service's `logDomainError` lines carry fixed diagnostics + correlation ids (reference, ids, code) — the pattern 4.1 pinned; the provider transaction reference never appears in a log bag.
