## 7.2.SEC (security audit)

- **REQ-044 (BOPLA)**: the mutation input whitelist carries exactly `input.planId` — no amount, currency, billing, or identity field ever leaves the client (test-pinned: the fixtures' mock request shape is the compile-time `PurchaseSubscriptionPlanMutationVariables` shape; an excess property fails `tsgo`). Prices render from the catalog row's decimal string, never computed client-side.
- **REQ-045 (student-only guard)**: the page runs `withPageAuth({ roles: [UserRole.Student] }, redirectTo: "/student/plans")` — anonymous → `/login?redirect=…`, role mismatch → their role dashboard; the container performs no role logic; `planCatalog` is authenticated server-side with no identity input. No BOLA/BFLA surface: no ids accepted from the wire, no client-side tenancy decisions.
- **Idempotency key**: minted client-side into a `useRef`, travels ONLY as the `x-idempotency-key` context header (never the input DTO), rotated only on success — replay-safe by the same contract as the broadcasts compose-send precedent.
- No secrets, no `console.*`, no raw server data through labels (the lane map was namespace-owned localized copy — now removed with the lane line).
