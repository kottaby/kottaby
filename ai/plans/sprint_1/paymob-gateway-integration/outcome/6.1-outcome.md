# Task 6.1 — `checkout` locale namespace — Outcome

## Summary

Landed the `checkout` i18n namespace — the full copy corpus for the student subscription-purchase funnel — following the `wallet`/`plans` namespace structure exactly: a `CheckoutLabels` interface with per-key JSDoc, `en`/`ar` leaf consts compile-typed against it, a `defineNamespace` handle with the conventional `checkout.checkout` id, registration in `Translations` + both message bundles + the namespace barrel/registry, and a wallet-shaped parity suite (69 tests / 257 `expect()`) covering key-set parity, non-empty strings, interpolation arity/containment, Arabic singular/dual/plural grammar arms, registry wiring, sync resolution, unknown-locale fallback, and Arabic-script sanity.

The key inventory (54 keys: 51 strings + 3 typed interpolation functions) covers every user-facing string the funnel's three consumer surfaces render — nothing in 7.2/7.3/7.4 components needs hardcoded copy:

- **7.2 (catalog + checkout initiation):** page chrome + metadata, per-plan buy CTA, tier feature lines (sessions count, validity days, balance-lane labels + credit line), catalog empty state, confirm-dialog title/summary labels/secure-redirect note/confirm-cancel-busy buttons, and the mock-provider instant-activation notice.
- **7.3 (payment result):** metadata + checking/loading arm, success/failed/pending branch titles+bodies (guidance copy), retry CTA (returns to the catalog), view-subscriptions CTA.
- **7.4 (my subscriptions):** page chrome + metadata, list column labels + null-date placeholder, the COMPLETE `SubscriptionStatus` chip vocabulary (active/pending/expired/cancelled/suspended — the wallet namespace's "mirror every enum value" convention) plus the derived payment-failed chip, failed-payment guidance copy, empty state + browse-plans CTA.
- **Shared:** `genericError` for the MUI `Alert severity="error"` query-error arms (the wallet/sessions view precedent); transport errors stay in the `errors` namespace (`subscriptionPurchase` section — landed, untouched).

Arabic quality: natural RTL copy consistent with the established billing vocabulary (`خطة`/`اشتراك` domain terms from the `plans` namespace, `ج.م`-adjacent money copy left to `Intl` per REQ-054, `معلّق`/`فشل الدفع` chips consistent with the wallet/notification namespaces); the two count-bearing lines are grammar-aware (singular/dual/plural arms pinned by tests — the `adminSessionGovernance` `countLine` precedent). Money VALUES are never keyed: REQ-054 renders amounts via `Intl`/`toLocaleString` from server-provided decimal strings, so the namespace owns labels only (`amountDueLabel`).

## Semantic review checklist (6.1.SR)

- **No dead branches:** the two Arabic grammar functions expose 4 arms each, every arm test-pinned (`1`/`2`/`8`/`12` sessions; `1`/`2`/`7`/`30` days) and every arm reachable within the plan/subscription validation ranges (session count 1–1000000, interval days 1–3650); the zero-count arm is deliberately ABSENT (unreachable by validation — unlike list-count lines, a plan always carries ≥1 session/day). All 54 keys map to mandated consumer surfaces (7.2/7.3/7.4 acceptance criteria + REQ-065's default/loading/empty/failed/pending storybook arms).
- **No cross-layer imports:** every import inside the 11 files is `@/shared/locale/**` or `bun:test` — `shared/` never reaches `frontend/`/`backend/`/`app/` (the types interface references no view or codegen types).
- **Interpolation types exact:** the three function keys are typed on the interface (`(count: number)`, `(days: number)`, `(laneLabel: string)`) and BOTH leaves are compile-typed `CheckoutLabels` — an arity/type drift fails `bun tsgo`; the runtime belt pins `.length === 1` per locale and interpolation containment.
- **Enum-mirroring convention:** `statusActive/Pending/Expired/Cancelled/Suspended` mirror EVERY `SubscriptionStatus` value and `laneHifz/Tajweed/Reviews` mirror EVERY `SubscriptionCreditLane` value (the wallet namespace's ledger-type/status vocabulary precedent); `statusFailed` is the documented DERIVED chip (payment-status-driven, not a subscription-status value).
- **Stateless modules:** all leaves/handles are `const` object literals + pure functions; no module-level mutable state anywhere.

## Security review (6.1.SEC)

The namespace holds **no secrets, no user data, and no injection surface**: plain string literals + typed template functions with named arguments only — no HTML, no URLs, no provider references, no amounts (money renders via `Intl` from server-provided decimal strings per REQ-054, so no client-side float math and no number formatting keys to poison). The lane label passed into `laneCreditLine` is itself a namespace-owned localized literal (never raw server data), matching the repo's no-raw-data-through-labels discipline. No BOLA/BOPLA/BFLA surface exists — the files define copy, not code paths.
