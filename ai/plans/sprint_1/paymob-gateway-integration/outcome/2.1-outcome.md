# Task 2.1 — Paymob env configuration — Outcome

## Summary
Extended the backend environment seam with provider-facing Paymob gateway configuration and dev-tunnel (ngrok) configuration: a 10-field `paymob` member and a 3-field `ngrok` member on `EnvironmentConfig`, two new parsing helpers, five new documented defaults, and a `getPaymobConfig()` getter that reads through the pre-existing cached snapshot. Added full unit coverage (75 tests, all passing), a pinned test-CI unset-key list, and operator documentation in `.env.example` (13 keys, placeholders only). All quality gates green.

## Files modified
- `backend/lib/env.ts` — `EnvironmentConfig.paymob` (secretKey/publicKey/hmacSecret/apiKey: `string | null`; integrationIdCard/integrationIdWallet: `number | null`; apiBaseUrl/checkoutBaseUrl: `string`; httpTimeoutMs/reconcilePendingMinutes: `number`) and `EnvironmentConfig.ngrok` (`authtoken`/`domain`: `string | null`; `port`: `number`). New helpers `parseOptionalIntegerEnv` (strict non-negative decimal integers, everything else → `null`) and `nullableSecretEnvValue` (trimmed value, missing/empty/whitespace-only → `null`). Defaults: `DEFAULT_PAYMOB_API_BASE_URL` = `https://accept.paymob.com`, `DEFAULT_PAYMOB_CHECKOUT_BASE_URL` = `https://eg.checkout.paymob.com`, `DEFAULT_PAYMOB_HTTP_TIMEOUT_MS` = 10000, `DEFAULT_PAYMOB_RECONCILE_PENDING_MINUTES` = 30, `DEFAULT_NGROK_PORT` = 3000. New getter `getPaymobConfig()` following the existing getter pattern.
- `backend/lib/env.test.ts` — new paymob/ngrok suites: registry inclusion (every key observable through its typed member), invalidation coverage (stale → reset → re-read → inert after removal), typed defaults (inert snapshot, nullables never empty-string/guessed numbers), parsing boundaries (integer coercion, positive-int fallbacks, verbatim URL acceptance, whitespace-only → default, port bounds), security posture (secrets only on paymob members, frozen unset-key list, no NGROK_* in it). Reuses the file's established snapshot/invalidate test idioms.
- `backend/lib/test-ci-env.ts` — added `TEST_CI_UNSET_PAYMOB_ENV_KEYS`: frozen list of exactly the ten `PAYMOB_*` keys test CI leaves unset (NGROK_* deliberately excluded so the tunnel callback channel can never be selected in test CI). Consistent with the module's existing test-mode helper pattern.
- `.env.example` — new "Payment Gateway — Paymob" and "ngrok tunnel" sections: 6 active `PAYMOB_*` keys with `<your-…-here>` placeholders, 4 commented `PAYMOB_*` tuning keys with documented defaults, 3 commented `NGROK_*` keys, plus explanatory comments (dashboard provenance, server-side-only secrets, fail-closed unset semantics). No real credential values.

Files NOT modified: none — scope boundary respected (exactly the four planned files).
