# Task 3.2 — Paymob mappers — Outcome

## Summary

Landed the Paymob mapper module as three pure functions over explicitly passed arguments (`paymob.mapper.ts`) plus a colocated 28-test suite: `buildIntentionRequest` (strict integer-cents conversion with a 2-decimal-place/safe-integer guard, the `"NA"` billing placeholder matrix, integer integration IDs with the wallet appended only when configured, verbatim `special_reference` and callback URLs), `toCheckoutDescriptor` (presence validation of the intention response's identity members → domain error; checkout URL assembled from the configured prefix plus exactly the two documented query parameters; enum-value provider; the handed-in correlation key echoed as `providerReference`), and `mapCallbackToEvent` (terminal-success-only confirmation, cents→decimal-string amount, stringified transaction id, null merchant echo → unresolvable empty reference). No I/O, no environment reads, no logging, no module state — the 3.3 adapter owns config resolution, HTTP, retry, and logging and passes everything in.

## Files created

- `backend/services/billing/payment-gateway/paymob/paymob.mapper.ts` — pure mappers (module docblock states the boundary rules; helper functions are private):
  - `convertAmountToCents` (private): regex `/^\d+(\.\d{1,2})?$/` then exact string-split integer math (`whole*100 + fraction.padEnd(2,"0")` — no float round-trip) and a `Number.isSafeInteger` ceiling; rejections throw `ValidationError` (code `VALIDATION`) BEFORE any network call: >2 fraction digits, non-numeric/empty/dot-shaped/scientific text, sign prefixes (negatives included), and cent values beyond `Number.MAX_SAFE_INTEGER`. `"0.01"`→1, `"0.1"`→10 (one fraction digit is ≤2dp — allowed), `"250.00"`→25000, whole-number strings without a dot allowed, `"90071992547409.91"`→`Number.MAX_SAFE_INTEGER` accepted, `"0"`→0 (format-valid; positivity is owned upstream by the catalog/purchase flow, which never issues free-plan purchases through the real gateway).
  - `buildBillingData` (private): `first_name`/`last_name`/`email`/`phone_number` are trimmed server-derived values with `"NA"` fallback when null/empty/whitespace-only (phone arrives nullable per the A1 port contract); the seven address members (`apartment`, `street`, `building`, `city`, `country`, `floor`, `state`) are ALWAYS `"NA"` — the domain carries no address data and none is fabricated.
  - `buildPaymentMethods` (private): `[integrationIdCard]`, plus `integrationIdWallet` only when non-null (a wallet deployment is an operator choice); values are the config's integers verbatim.
  - `buildIntentionRequest`: `amount` = the single conversion; `items` = one line item (`name` from args, same cents, `quantity: 1`) so the vendor's "sum of item amounts must equal the total" rule holds by construction; `currency` passthrough (the EGP/integration-currency match is an operator configuration responsibility per REQ-013's rule, checked by the provider); `special_reference` = `input.specialReference` verbatim; `notification_url`/`redirection_url` = the caller-resolved args.
  - `toCheckoutDescriptor`: guards `id`/`client_secret` presence (`typeof !== "string"` or empty → `DomainError("SERVICE_UNAVAILABLE", …)` — the response crosses the network boundary so members are trusted only when present; the upstream body is never rethrown, and the sanitized upstream log line belongs to the adapter); returns `{ provider: PaymentGateway.Paymob (enum VALUE import), providerReference: specialReference (the handed-in correlation key — deliberately NOT `response.special_reference`, test-pinned), checkoutUrl: `${config.checkoutBaseUrl}?publicKey=${config.publicKey}&clientSecret=${response.client_secret}` }` — exactly the two documented parameters, no path appended (the configured prefix is a full host(+path) value owned by the environment snapshot; both the default host-less form and the legacy `…/unifiedcheckout/` form assemble correctly, test-pinned).
  - `mapCallbackToEvent`: `reference = obj.order.merchant_order_id ?? ""` (a verified callback without the merchant echo cannot resolve to a purchase — the empty reference makes fulfillment treat it as an unknown payment, the ack-no-op path); `outcome = obj.success && !obj.pending ? "confirmed" : "failed"` (a success still pending has not moved money); `amount = (obj.amount_cents / 100).toFixed(2)`; `currency` verbatim; `providerTransactionId = String(obj.id)`.
- `backend/services/billing/payment-gateway/paymob/__tests__/paymob.mapper.test.ts` — 28 tests / 63 `expect()`: full intention-body field-by-field deep equality; line-item==total invariant; wallet-absent matrix; integer method IDs + verbatim correlation key (incl. a wallet ID of `0` — only `null` means absent); URL/currency passthrough; billing placeholder matrix (null phone, empty/whitespace members, trimming of usable values, all-address-members `"NA"`); cents guard matrix (2dp/1dp/whole/zero accepted; `"1.234"`, `"abc"`, `""`, `"12."`, `".5"`, `"1e3"`, `"-1.00"`, `"+1.00"`, safe-integer-overflow rejected; `MAX_SAFE_INTEGER` boundary accepted); URL assembly pinned for the path-less default prefix AND a path+trailing-slash prefix; enum-value provider; reference-echo distinction; missing `id`/`client_secret` → `DomainError`; callback mapping (terminal success confirmed, success+pending failed, declined failed, sub-unit amount conversion `1→"0.01"`/`5→"0.05"`/`999999→"9999.99"`/`0→"0.00"`, currency verbatim, numeric-id stringification incl. a >2^32 id, null `merchant_order_id` → empty reference with the outcome still mapped).

Files NOT modified: `paymob.types.ts` (DTOs consumed as landed), `paymob.constants.ts`/`paymob.hmac.ts` (mappers sign nothing — HMAC is the adapter's job), `payment-gateway.types.ts`, env files, everything else. Scope boundary: exactly the two new files.

## Security (3.2.SEC)

- No client-derived money fields: the amount comes from `PaymentCheckoutInput.amount` (server-side, copied verbatim from the freshly-read plan row per the port contract); billing comes from the server-derived `billing` block; the mapper never sees request payloads. The guard converts rather than trusting — a malformed amount fails closed pre-network.
- No secrets in strings: the only config member consumed is `publicKey` (the provider-documented client-safe key, part of the checkout URL by design); `secretKey`/`hmacSecret`/`apiKey` are never read by the mapper. Nothing logged anywhere in the module.
- Checkout URL carries exactly the two documented parameters — no hidden extras, no echo of other response members.

## Carry-forward knowledge (for later tasks)

- **3.3 adapter** (first consumer): resolve `PaymobResolvedConfig` (fail-closed guard) + both URLs, call `buildIntentionRequest` → POST via the HTTP client → `toCheckoutDescriptor(response, config, input.specialReference)`; on `DomainError("SERVICE_UNAVAILABLE")` from the descriptor validation, log the sanitized upstream status server-side and surface the generic "payment unavailable" error. The mapper intentionally does NOT log — that's the adapter/route layer's job.
- **Exact URL assembly rule**: `checkoutUrl = config.checkoutBaseUrl + "?publicKey=" + config.publicKey + "&clientSecret=" + response.client_secret` — the configured prefix carries ANY host/path (default `https://eg.checkout.paymob.com`; legacy `https://accept.paymob.com/unifiedcheckout/` works, trailing slash or not); the mapper appends only the two-param query. 7.2's frontend just redirects to this string.
- **Placeholder matrix** (reusable for docs/9.2): trim-then-`"NA"` for `first_name`/`last_name`/`email`/`phone_number` (phone nullable upstream); ALWAYS `"NA"` for `apartment`/`street`/`building`/`city`/`country`/`floor`/`state`.
- **Cents guard**: regex `^\d+(\.\d{1,2})?$` + exact string-split integer math + `Number.isSafeInteger` ceiling; `ValidationError` pre-network. Zero is format-valid (positivity enforced upstream); one fraction digit is allowed. The same guard applies if 7.2 ever needs to display plan-price validation feedback.
- **Callback mapping contract** (4.1/4.2): null `merchant_order_id` → `reference: ""` → the activation service's reference lookup misses → unknown-payment ack/no-op; `providerTransactionId` is always present for transaction callbacks (A2 persistence); amount string is `toFixed(2)` of the verified cents — the activation layer's amount comparison can expect exact string equality against the stored payment row.
- REQ-015's "domain provider error" is materialized as `DomainError("SERVICE_UNAVAILABLE", …)` (registered code, 503 surface, matches the "payment unavailable" client surface); no bespoke error class was added to the hierarchy.
