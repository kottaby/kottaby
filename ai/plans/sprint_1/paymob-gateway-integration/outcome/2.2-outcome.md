## Semantic review checklist
- **Idempotency / convergence**: PG side `ADD COLUMN IF NOT EXISTS` + `CREATE OR REPLACE FUNCTION`; SQLite side `ADD COLUMN IF NOT EXISTS` + DROP/CREATE TRIGGER — safe to re-run any number of times, and fresh DBs converge because 3 → 4 → 5 amend the guard in alphabetical order.
- **Guard soundness**: the allowance disjunct (`NEW IS NOT DISTINCT FROM OLD OR OLD IS NULL`) fails both arms for value→value and value→NULL; the whole branch still requires `OLD.status='pending' AND NEW.status IN ('paid','failed')`, so the reference is writable only inside the guarded decision. `subscription_id` remains `IS NOT DISTINCT FROM`-guarded (FK set-null stays unreachable). Trigger message text extended; tests assert both the immutable substring and the transition-permitted clause.
- **Read parity**: tx path and `queryDb` path use the same predicate (`gateway AND status='pending' AND created_at < olderThan`), same ordering (`created_at ASC, id ASC`), same `LIMIT` — the parameterized values (`gateway`, `PaymentStatus.Pending` as VALUE, `olderThan`, `limit`) go through bind params, never string interpolation.
- **LEFT JOIN choice**: `subscription_id` is a nullable FK, so an INNER JOIN could silently drop a ledger row whose subscription reference is missing from the sweep batch; the LEFT JOIN keeps the row and degrades `paymentReference` to `null` (caller fails over to another correlation key). `subscriptions.payment_reference` is the gateway-issued merchant-order key (partial unique index, migration `20260907182455_ancient_scarecrow`) — the only existing column that maps a pending payment to a Paymob order, which is what the reconcile caller's transaction inquiry must be addressed by.
- **Plan-meta comments**: none — grep for `A4|REQ-|Task 2.2|paymob-gateway-integration` over `backend/db/**` and `backend/drizzle/**` returns nothing; all new comments are domain-behavior prose.
- **Drizzle plumbing (no `_journal.json`)**: this repo's drizzle-orm migrator does NOT use a journal — `readMigrationFiles` throws if `meta/_journal.json` exists and instead scans `backend/drizzle/*/migration.sql`, sorting by folder name. Ordering convention is therefore lexicographic, and the new pair reproduces the landed precedent exactly: `…_custom_2-functions` sorts before its schema sibling `…_omniscient_karen_page` (migration 2), and `20260911175854_custom_5-…` sorts before `20260911175854_sweet_ted_forrester` (custom SQL first, then schema delta — both idempotent, either order converges). Snapshot format/prevIds chain matches the repo's other v8 snapshots.
