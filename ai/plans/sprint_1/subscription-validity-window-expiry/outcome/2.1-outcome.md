## Summary

Added one entry to the `subscriptions` pgTable third-argument index array:

```ts
index("subscriptions_active_end_date_idx").on(t.endDate).where(sql`${t.status} = 'active'`)
```

- Uses the exact same `.where(sql`…`)` idiom as the existing partial unique index `subscriptions_payment_reference_unique` in the same file — a `${t.status}` column reference interpolated into a `sql` template, compared against the `subscription_status` pgEnum value `'active'` as a plain SQL literal. Drizzle interpolates the column (producing `"subscriptions"."status"`) and emits the rest as static SQL; no bound parameters, no drift between schema and DDL.
- `sql` was already imported from `drizzle-orm` at the top of the file (`subscriptions.ts:1`) — no import changes needed.
- ZERO `--` or `/* */` comments inside any `sql` template (the anti-pattern is impossible here: the template contains only the column reference and the literal comparison).
- No comments were added at all; nothing else in the file was touched (verified via `git diff`: exactly 1 inserted line).

## Carry-Forward Knowledge

- The index is **non-unique and partial**: `WHERE status = 'active'` keeps the index tiny (only in-window subscriptions) and near-zero write cost for pending/expired/cancelled/suspended rows — the rationale ratified as Decision D5 (rejected alternative: full composite index).
- The sweep's guarded UPDATE (`... WHERE status = 'active' AND end_date IS NOT NULL AND end_date <= now()`, tasks 4.1/5.1) is the intended consumer; it can use an index range scan on `end_date` under the partial predicate. Do not "simplify" the predicate to `status <> 'expired'` etc. — the Drizzle declaration and the repo guard predicate must stay aligned (`status = 'active'` literally).
- The predicate embeds the enum value as a SQL literal inside the Drizzle schema file (same idiom as `subscriptions_payment_reference_unique`). If the `subscription_status` pgEnum value string ever changes, this template must change with it — flagged for the enum-widening reviewers (no TS enum import is used here, so no import-graph coupling exists).
- Drizzle emitted `WHERE status = 'active'::subscription_status` in DDL (enum literal cast) — semantically identical to the declared predicate; future `db push` runs are stable (proven drift-free).
- Parallel-wave tree state: sibling tasks 2.2 (types) and 2.3 (locale keys) edit disjoint files; their diffs were present in the tree during this task's verification and did not interact with the schema change (tsgo remains 0 errors with all three waves applied).
