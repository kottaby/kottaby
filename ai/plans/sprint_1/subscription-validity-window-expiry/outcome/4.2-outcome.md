## The load-bearing semantic this task implements (ledger D1 → O1)

Per plan.md Decision D2 (§2.1), AC2's "zero the expired period's remaining balance" is implemented as **O1 — conditional lane zeroing**, because the shipped balance model is flat per-student lane counters with no per-subscription attribution:

> When a subscription expires, the plan's `balance_lane` credited to the owning student is zeroed **only if** no other `active` (post-flip, in-window by construction) or `pending` subscription of that student credits the same lane — one guarded UPDATE per (student, lane) inside the sweep transaction; `balance_trial` is structurally unreachable.

Load-bearing properties carried by this task's code:

1. **Coverage guard = `NOT EXISTS (subscriptions ⨝ plans WHERE s.user_id = $1 AND p.balance_lane = $lane AND s.status IN ('active','pending'))`.** `active` at zeroing time is exactly "in-window at the captured `now`" *because the batch flip runs first in the same sweep transaction* (no date comparison needed here — this method is the (student, lane) zeroing primitive the service calls post-flip). `pending` counts as coverage (ratified guard; the under-revoke direction is the deliberate conservative choice — Revoke-Never-Wrongly).
2. **Lane-positivity guard = `COALESCE(balance_<lane>, 0) > 0`** — already-zero lanes collapse to a zero-row no-op, making sweep replay provably idempotent (honest `lanesZeroed` counting: `true` iff the row matched).
3. **`balance_trial` is structurally exempt** (trial is not subscription-bound, INV-B3's exemption): the zeroing column is resolved exclusively through a frozen map keyed by `SubscriptionCreditLane` — a vocabulary with **no trial member** — so no caller input, string, or future refactor can ever target `balance_trial` through this write. Pinned three ways: TypeScript (`Record<SubscriptionCreditLane, AnyPgColumn>` compile-exhaustive), source pin (map has exactly `[Hifz]`, `[Tajweed]`, `[Reviews]` keys, no quoted string keys, no trial key), and runtime probe (an out-of-vocabulary lane resolves no column and never issues an UPDATE).
4. **Ownership is fused into the statement** (`students.id = $1` AND `s.user_id = $1`): the guard can never observe another user's subscriptions, and one student's zeroing can never touch another student's row — no read-then-write, zero TOCTOU (the WHERE predicate is the lock, same mechanics as `decrementLaneIfAvailable`).

Known residual (recorded in ledger D1, not a defect of this task): under shared-lane co-subscriptions O1 under-revokes the expiring period's residual — inherent to flat lanes; O2 (attribution ledger) remains the recorded future-work refinement.

## Security audit (4.2.SEC)

- **BOLA/IDOR / cross-student zeroing:** impossible by construction — the UPDATE predicates key on `students.id = $1` (row identity) and the coverage anti-join keys on `s.user_id = $1` (same bound value; `students.id` is the shared user PK). Proven behaviorally by the ownership probe test in both directions (another student's subscription is neither coverage for me nor affected by my zeroing).
- **BOPLA (column injection):** the lane column is resolved ONLY via the frozen, enum-keyed `ZERO_LANE_BALANCE_COLUMNS` map — `Record<SubscriptionCreditLane, AnyPgColumn>` (compile-exhaustive) + `Object.freeze` (mutation-proof) + `sql.identifier(column.name)` (identifier-safe). Caller strings cannot select a column; an out-of-vocabulary runtime key resolves `undefined` and the statement is never built (proven). No `{...input}` spreads, no `sql.raw`, no string-built identifiers, no `--` sequences.
- **No input bodies, no user-facing strings, no logging** in the repo layer (repo AGENTS compliance); the method raises nothing — misses are honest `false` returns for the service to count.
