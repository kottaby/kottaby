## 1. Summary

The portal root now resolves the completion-notification deep link end-to-end client-side. The server shell (`app/(dashboard)/parent/children/page.tsx`) extracts the raw `?session=` value with the detail shell's `firstValueOf` pattern and forwards it as a plain prop — still guard-only (zero data fetch, zero server redirect). The root container resolves the pointer through a new single-responsibility hook (`useSessionResolution`): a skip-guarded `useQuery(parentSessionTargetQueryDocument)` (skipped when no pointer is present AND when the pointer is unusable — no network probe for empty/non-numeric/non-positive values), and on success ONE `router.replace` to the canonical report landing `/parent/children/<studentId>?tab=reports&session=<id>`, composed by the detail container's own `buildDetailUrl` (no parallel URL builder), written exactly once per resolved pointer (ref-ledger gated). On any resolution failure (FORBIDDEN denial, network, malformed pointer — indistinguishable by construction) the transient localized notice `t.sessionTargetUnavailableNotice` renders and navigation ownership releases to the pre-existing first-child auto-select. While the pointer is pending or has landed, the auto-select gate is closed — the two effects can never both replace. All decision logic lives in a pure module (`ParentChildrenRootContainer.helpers.ts`) pinned by a new 19-test suite.
