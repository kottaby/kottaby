### 4.3 SEC (3.1.SEC) — security & tenancy audit

- **BOLA/IDOR:** identity is `ctx.user.id` ONLY — the field takes no parent-id argument; the resolver forwards exactly `(ctx.user.id, args.sessionId, ctx.locale)`. A prober cannot resolve a session whose family is not theirs: the found row's `studentId` is gated by `requireLinkedChild(parentActorId, row.studentId, …)` BEFORE the pair is returned (composite relation gate), and the linked child is verified, not assumed.
- **BFLA:** `authScopes: parentOnlyAuthScopes` (the shared `$all { authenticated: true, role: [UserRole.Parent] }` conjunction) rejects anonymous (401/UNAUTHORIZED) and wrong-role (403/FORBIDDEN) callers pre-service; defense-in-depth `requireActor(…, UserRole.Parent, …)` re-checks inside the service (the service suite proves a non-parent actor is denied before any data read).
- **Constant-denial oracle:** missing / foreign / unlinked / severed session ids are indistinguishable — the same constant localized `ForbiddenError(t.forbidden)` (the null-session arm throws the SAME copy the link gate throws). A non-positive/non-integer `sessionId` collapses to `ValidationError` — never a 500 (the wire's `Int!` guarantees integer-ness; 0/negative integers legitimately surface as VALIDATION, not FORBIDDEN — the oracle covers existence/ownership, not shape).
- **BOPLA / output side:** zero input spread anywhere (the resolver forwards the single `sessionId` arg); the denial log carries `{ code, entity: "sessions", entityId, locale }` ONLY — no session row fields (teacher/student/status/fee columns never enter logs); the success projection is the closed two-field pair (nothing about the session's content crosses the boundary).
- **Read-only posture:** zero mutations registered; zero writes in the flow (a pure read inside a read-only transaction).
